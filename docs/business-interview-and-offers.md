状态：本地研究准备已实现；尚未开展真实访谈、报价联络、收费、客户资料处理或交付。默认报价注册表为空，消费者研究卡关闭。本文件的表格是填写模板，fixture 的编号与金额是虚构测试数据，不能改名后充当真人证据。

## 访谈样本与记录模板

首轮访谈 5–8 位**近期实际承担日本餐厅资料维护工作的人**。使用下面 8 个候选位置；实际找到谁才填写谁，未招募的位置保持空白。一个人的多次访谈只计一个维护者；自称感兴趣、一般食客或仅转发内容的读者，不自动计入实际维护者。各位置是研究方向，不是假定这些客户已存在，也不要求凑齐各类人数。

| 位置 | 候选实际维护者 | 该次访谈额外要核实的工作 | 参与者编号 / 最近任务证据 / 日期 |
| --- | --- | --- | --- |
| I01 | 管理多个餐饮客户的营销代理商运营者 | 多账号与分店混淆，客户修改要求、交付使用者 | 待填写 / 待确认 / 待填写 |
| I02 | 另一家独立代理商的维护负责人 | 跨客户重复核验、权限和人工容量，避免同团队重复样本 | 待填写 / 待确认 / 待填写 |
| I03 | 美食媒体的编辑或资料校对者 | 文章／清单更新触发，错链更正和最终发布责任 | 待填写 / 待确认 / 待填写 |
| I04 | 持续经营餐厅清单的媒体／创作者运营者 | 维护结果是否被用于真实工作，读者反馈造成的返工 | 待填写 / 待确认 / 待填写 |
| I05 | 餐饮企业内部维护多店资料的运营者 | 店铺身份、营业状态与预约入口分别由谁确认 | 待填写 / 待确认 / 待填写 |
| I06 | 长期维护日本餐厅条目的高频独立维护者 | 更新频率、首次和再次核验的差异，现有替代方法 | 待填写 / 待确认 / 待填写 |
| I07 | 有条件性入口／规则维护需求的代理商或编辑 | 规则变化、未知项处理，是否接受有边界的交付 | 待填写 / 待确认 / 待填写 |
| I08 | 不愿付费或曾停止类似维护服务的实际维护者 | 停用原因、实际预算拥有者、什么结果仍不值得买 | 待填写 / 待确认 / 待填写 |

每人使用同一份主模板，先追问最近一次工作，再展示相同版本报价。没有最近任务证据时记录缺口，不能用承诺补齐。参与者编号是研究域内随机／不透明编号，不使用姓名、邮箱、账号或真实客户名。

| 记录项 | 填写方法 |
| --- | --- |
| 研究记录 | protocolVersion、interviewId、日期、采访者内部编号、受访者编号、细分角色、同意范围；实际维护资格仍待负责人核实 |
| 最近具体任务 | 日期、目的、实际条目数量、工作输出及使用者；允许仅描述脱敏结构，不索取私人账号、DM、未经许可客户资料 |
| 更新触发与频率 | 什么变化导致重查；主动定期维护、客户请求或错误更正；真实上次与本次间隔 |
| 替代工作路径 | 使用哪些工具、从哪里开始、何时需要官网／预约平台、哪些步骤由谁负责；不请求登录或读取私密会话 |
| 工时 | 首次核验、重复核验、纠错、沟通、返工、客服分别记实际分钟和未知项；零工时须明确确认 |
| 错误后果 | 最近发生过什么错误、如何发现、修复和通知，谁承担影响；没有发生记录“未观察到”，不编造事故 |
| 输出实际用途 | 最近报告是否被打开／用于编辑／转交客户；只说“有帮助”与实际使用分开 |
| 权限与数据 | 哪些字段可提供、处理、存储和交付；来源许可未知就未知，不以客户同意替代第三方许可 |
| 决策人与预算 | 谁拥有购买决策；实际预算是否可说；未提供时留待确认，不从职位猜价格能力 |
| 报价回应 | offerId、offerVersion、完整价格／币种／周期／税费，逐项问是否接受**这一版本**；不把“喜欢”写成接受报价 |
| 真实任务提供 | 是否另行授权提供限定字段的实际任务；只记录受控证据引用与范围，不把原始资料加入匿名日志 |
| 拒绝／不确定 | 价格、范围、可信度、更新节奏、交付责任或预算障碍分别记；不诱导接受 |
| 后续 | 有无同意后续联络、联络存放位置及到期；未获授权不发送、不采集联系方式 |

可使用的日文追问：

- 「直近で店舗情報を確認・更新した仕事を、一つ教えてください。何件を、誰のために確認しましたか。」
- 「初回の確認と、後日の再確認には、それぞれ何分かかりましたか。分からないところは分からないままで大丈夫です。」
- 「間違いや古いリンクに気づいたとき、誰がどう直しましたか。作成した一覧は、その後どの仕事で使われましたか。」
- 「この範囲・期間・税込／税別の価格を、一つの見積もりとして受け入れますか。興味があるだけの場合は、別に記録します。」
- 「実際の確認作業を提供できる場合、どの項目まで扱ってよいですか。契約・支払い・提供開始は別途確認します。」

不能未经批准执行招募、联络、传输客户资料、付费竞品购买、上游付费调用或真实服务。访谈模板完成不代表上述动作获得批准。

## 冻结报价模板

业务维护与消费者研究各有独立 offerId 和 offerVersion。任何价格、币种、周期、范围、履约、退款、数据或容量变化都创建新版本。旧接受绑定旧版本，不自动迁移。真实价格尚未选定；历史消费价格猜想不作为售价，fixture 金额不作为报价。

| 字段 | 业务维护报价草稿 | 消费者研究报价草稿 |
| --- | --- | --- |
| 身份／状态 | maintenance-draft / draft-v1；draft；未激活 | consumer-draft / draft-v1；draft；未激活 |
| 价格／币种／税费 | 金额 null（待确认）；JPY 仅作草稿币种；税费待确认 | 金额 null（待确认）；JPY 仅作草稿币种；税费待确认 |
| 周期及有效时间 | 明确起止日期、周／月次数和报价到期；当前模板待负责人冻结 | 一个有限方案，明确一次／周期、起止与到期；待冻结 |
| 条目与核对次数 | 每客户最多 20 条；每条本周期次数待确认；首轮最多 3 客户 | 一个有界方案；条目／次数由成本证据决定，不承诺无限预览 |
| 字段／来源 | 列出身份、营业状态、入口和已核对条件中实际包含哪些；来源逐项许可 | 同样明确覆盖字段与允许来源；不复制禁止第三方内容 |
| 服务语言／时段 | 日语优先；实际人工时段、响应和交付天数待确认 | 任务完成后自愿研究；不阻断主流程；实际履约待确认 |
| 未解决项／保证 | unknown / conflict 给原因和下一动作；不提供实时空席或预约成立保证 | 有依据的信息不足不等于找到可订座席；明确此范围 |
| 验收／修订 | 客户审阅指定交付 revision；修改生成新 revision、新验收 | 结果核对范围、终结标准和问题反馈方法待确认 |
| 容量／调用上限 | 实际人工分钟和付费 API 次数均 null（待确认）；不能把 20 条当自动调用许可 | 同样待确认，已有全局预算仍是上限；不发真实套餐权益 |
| 退款／客服 | 政策、窗口、客服渠道待确认；确定前不能激活 | 同样待确认；没有支付入口、没有收款渠道声明 |
| 数据范围 | 仅获授权线索、自写资料、获许可来源引用；排除原图、DM、账号凭证、付款明细 | 匿名选择不含正文、联系信息、客户编号或付款资料 |
| 数据期限 | 研究原记录最多 30 天、不可反推汇总最多 90 天；真实商务记录另审 | 同样；候补联系未来独立存储，默认 90 天，不接入本轮模型 |
| 成本依据 | 报告版本、来源、币种、范围、组成与缺口均待确认 | 使用独立消费者方案的成本与价格证据 |
| 激活批准 | approvedActivation.state=not_approved；批准版本／引用／时间均 null | 同样默认关闭；缺任一必需项不能通过校验或接受价格信号 |

## 信号和门槛的独立口径

| 层 | 最少所需记录 | 不能代替它的记录 |
| --- | --- | --- |
| 兴趣 | 匿名 interested / not_needed / too_expensive / unsure 与报价版本 | 不是明确报价接受、签约或付款；不按事件推人数 |
| 明确价格接受 | 同一 offerVersion、完整币种金额周期范围、脱敏证据引用 | “喜欢”、候补联系或另一版本接受 |
| 签约 | 独立合同事实与时间／受保护引用 | 不等于到账、履约或来源核验 |
| 提供真实任务 | 获授权任务范围与受控引用 | 同意访谈或接受价格 |
| 付款 | 指定周期、币种金额、对账证据；reconciled 与 payment_unverified 分列 | 合同、转账截图、客户口述或续费开关 |
| 交付 | 周期与明确 deliveryRevision | 付款或已创建草稿 |
| 验收 | 客户审阅的相同周期／revision 与独立验收证据 | 交付；验收也不抬高来源可信度 |
| 续购 | 新周期真实到账，关联原周期 | 愿意续用、免费延期、自动续费设置；续购未交付／验收不通过 GB |
| 退款 | 独立退款事实与金额币种，保留历史、修正实收 | 删除订单或覆盖旧付款 |

事实无需按单一接收顺序到达。重复 factId 幂等；不同内容复用同一个 ID 时整组留缺口。相同付款证据重复计一次；跨客户／周期／币种／金额复用同一付款证据时，不计任何冲突用途。金额或币种与报价不符时待核对，不能列为此版本明确接受或已付转化。

G1 需要 GQ 可复核证据、5–8 位实际维护者访谈、至少 2 位接受**同一版本**明确价格范围且提供真实任务，服务字段、许可、周期、人工容量与费用可执行。G1 只是开始试点的意向条件。

GB 需要至少 2 位客户逐人完成实付首周期和按该价格付费续购周期的交付、验收，逐周期完整成本下获客前后贡献为正，字段权限与容量可持续。业务付款不代替消费者付款。离线工具只汇总输入声明，G1／GB 始终 `evidence_insufficient`，不会因数量、synthetic、声称批准或本地标签而通过。

## 本地模型与接口

实现：`server/offer-research.mjs`；fixture：`eval/offers/fixtures.mjs`；测试：`test/offer-research.test.js`。所有 schemaVersion 均为 1，未知版本和未知字段拒绝；金额为整数最小币种单位（JPY=0 位，USD／EUR=2 位）。新增币种需明确单位并升级约定，不默认换算。

- `validateOffer(body)` 校验 consumer / business_maintenance、版本、价格周期、范围、最多 20 条、首轮维护最多 3 客户、履约退款、数据范围、成本依据和 approvedActivation，返回 `{valid, errors, offer}`。draft 的价格／容量／成本可为显式 null。active 必须项不能缺失，synthetic 不能激活。
- `getOfferResearchConfig()` 返回冻结的 `{schemaVersion:1, enabled:false, offers:[], choices, sourceContexts}`。可传服务器审核的 `{enabled, offers}` 和当前时间；只投影 consumer 方案，剔除内部成本和批准证据引用。默认空表；可选 fixture card 仍为 inactive，所有公开投影 `researchOnly:true`、`purchaseAvailable:false`。
- `validateConsumerPriceSignal(body, config, now)`（别名 `validatePriceSignal`）只接受 `schemaVersion/offerId/offerVersion/choice/sourceContext`，choice 为上表四种匿名选择，sourceContext 为 `completed_analysis/completed_review/unknown`。config 必须是本模块生成的服务器持有对象，不能用 JSON 重建副本或客户端对象启用。未启用／到期返回 inactive_offer；版本不匹配返回 unknown_offer_version。sourceContext 是有限上下文标签，不能凭浏览器声明认定真人完成、自然流量或付费。
- `summarizeOfferResearch(snapshot)` 只接 schemaVersion、evidenceType 和 offers/interviews/priceSignals/commercialFacts 四个有界数组。evidenceType 仅 synthetic/local_unverified，最多 100 offer、100 访谈和总 10,000 行。局部非法记录固定码汇总并排除；顶层非法或越界拒绝。只输出按客群分离的计数、金额已知小计和缺口，不输出参与者、客户、证据编号、正文或原始资料。

消费研究接口必须保持独立于 CommercialEvent v2；普通事件不加入真实业务标签、合同或付款数据。A08 不实现写入存储、客户公网写接口、候补联系、邮箱验证、自动到期删除、支付／订单账本、套餐扣减或对外发送。未来受保护资料与删除工具另有前提；当前原记录最多 30 天、汇总最多 90 天由研究负责人在获授权真实研究前落实，不能声称本模块已经执行删除。

```sh
node scripts/summarize-offer-research.mjs
node scripts/summarize-offer-research.mjs --input /absolute/path/to/authorized-local-snapshot.json
node --test test/offer-research.test.js
```

默认 CLI 只读内置 synthetic，零网络、零真实数据、零外部写入。显式输入是单个本地 JSON（最多 5 MiB），不会自动搜索生产日志。读取失败只输出固定错误码，不回显文件内容或敏感错误详情。`--input` 是格式能力，不是处理真实客户资料的授权；本轮只运行 synthetic。报告 `realWorldEvidence:false`、`releaseGateEvidence:false`，未知成本仍待确认。

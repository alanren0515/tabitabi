# A 工程完成后的下一阶段进入包

日期：2026-10-03  
状态：真实研究与试点的准备清单；尚无本包所要求的 GQ、G1、GB 或 GR 通过证据。

本包承接 [下一轮路线图](./next-feature-roadmap.md#5-交付阶段与分支门槛)，用于在 A 工程验收后判断下一笔开发投入和真实执行范围。A 的技术完成、离线工具通过和 fixture 结果，都不能代替真实用户任务、客户付款、履约或自然复用。本包不新增研究阈值，也不执行招募、外联、客户资料处理、付费调用、收款、交付外发或上线；上述动作继续按目标、操作和上限分别取得适用批准。

工程进度与技术验证见 [实施记录](./implementation-progress.md)；本包只列真实进入条件。GQ/G1/GB/GR 是开发投入决策，不替代安全、成本和 [公开发布检查表](./formal-public-release-checklist.md)。

## 2. GQ：冻结后再采集三路线真人任务

依据：[M16 设计](./feature-module-designs.md#m16-同案例质量与效率评估) · [评估协议与基线说明](./benchmark-protocol.md)。

### 采集前冻结的输入

| 输入 | 可复核证据与限制 | 当前状态 |
| --- | --- | --- |
| 旧版 baseline | 保留 revision `6c1e1567ebb796af2f8dd19e001f3550303fc2c0`；按 `eval/benchmark/baseline-snapshot.json` 核对档案 SHA-256、配置、保留位置及重放命令。只有版本文字不够，档案／Git 都丢失则停止评估 | 已有本机保留机制；真人 baseline 任务尚未取得。未声称异地备份 |
| 新版 candidate | A 相关改动验收后确定实际可运行 revision，绑定研究版本；不得用占位版本或采集中途混版 | 正式真人研究 candidate 待冻结 |
| 三条必需路线 | baseline、candidate、唯一 primaryReference；默认 Maps＋官网／预约平台，冻结同一种具体操作路径及设备／地区可用性 | 真人主路线及可用性待冻结；直接竞品只可作次级诊断 |
| 案例及真值 | 至少 30 个有效去重案例；人工确认具体门店／分店、预期行动或 `unknown_required`、输入类型、证据引用、核验日和有效窗口；冻结 normal/hard 配比 | 真实名单、真值版本与有效窗口待取得 |
| 参与者与分配 | 10–15 位实际目标参与者；首版每案每条路线由不同参与者完成，路线任务数与首条路线人数平衡；每有效案例三路线各一条任务，至少 90 个分配任务 | 实际参与者、分配表与设备条件待取得 |
| 任务协议 | `protocolVersion`、`groundTruthVersion`、两版 revision、caseRoster、目标、完整任务计时口径、统一时间上限、rubric、起止时间；采集前冻结 | 真人协议尚未冻结；首轮 5 分钟为设计建议，实际统一上限仍须事前确定 |

每条任务记录唯一 task ID、案例／路线／revision、protocol／truth／rubric 版本、匿名参与者和人工审核者、设备／地区、顺序、开始／结束、终结状态、实际选择及审核原因。匿名编号不使用姓名、邮箱或账号；证据引用指向受控研究材料，不把原始内容写入产品日志。

原案例名单、分配总量与排除数一起保留。真值失效标记 `invalid_truth` 并说明原因，三路线对称处理；不得单删某一路线的失败。缺记录、失败、弃权、超时与错误未知保留在有效分母，额外重试不能覆盖原任务。若有效案例不足 30 或缺任一必需路线／任务时间，结论为证据不足。

### 判定证据

- candidate 相对 baseline 及 primaryReference 的全任务正确完成率、可行动解决率均不下降，并按案例检查无新增 `wrong_branch`／`unsafe_action` 等关键误导。出站点击不算正确完成，全部拒答不能通过。
- 再相对 primaryReference 满足其一：成功任务中位耗时下降 ≥25%；或难例关键错误减少，且常规成功任务中位耗时增加 ≤10%。API 响应耗时与完整用户任务耗时分开。
- 报告保留全部有效分配任务、可行动子集、失败／未知／弃权／超时、成功耗时样本数与分布、缺口、版本及人工评分依据。次级竞品不替换主路线，不参与本版通过逻辑。
- 证据完整但条件未满足是未通过；缺时、缺路、混版、未冻结或真值不完整是证据不足。小样本仅支持探索判断，不证明总体无风险、预约成立、付费意愿或商业可行。

研究原记录默认最多 30 天、不可反推匿名汇总最多 90 天，由研究负责人落实到期检查和清理。当前自动删除未实现，不可写成已执行。真实参与者联络、材料处理、付费识别或竞品购买须由对应授权覆盖，不能由本地命令的输入能力推断许可。

## 4. GB：逐客户、逐已履约周期验证续购贡献

依据：[客户周期成本报告](./customer-cost-reports.md) · [商业事实独立口径](./business-interview-and-offers.md#信号和门槛的独立口径) · [M07 维护报告](./feature-module-designs.md#m07-维护工作台与交付报告)。

GB 至少需要 2 位客户，**每位分别完成实付首周期和至少一次按该价格付费续购周期的交付与验收**。首周期与续购周期均须保留以下证据；续购只到账、未交付或未验收不能通过。

| 证据 | 核对内容与责任 |
| --- | --- |
| 报价与周期 | 商务负责人记录准确报价版本、金额／币种、周期边界、服务范围和续购关联；兴趣、签约、付款、交付、验收、续购、退款独立记录 |
| 实收与退款 | 对账负责人核实到账净额、金额／币种、独立脱敏对账引用。截图或客户口述不代替已核实到账；重复证据只计一次，跨客户／周期冲突保留缺口 |
| 交付与验收 | 运营负责人记录 `cycleId/deliveryRevision`、原分配条目、resolved/unresolved、原因与下一动作；客户审阅同一 revision 的独立验收证据。修改产生新版本和新验收，旧验收不迁移，客户验收不升级事实可信度 |
| 完整 API 与人工成本 | 保留失败、fallback、重复核验、纠错、沟通、返工和客服；任务／请求唯一归属；实际分钟与有效人工价格版本；账单或已确认用量 × 有效价格的保守上界，明确区分估算与已出账 |
| 其他成本与贡献 | 对账负责人核实额外客服、渠道／获客、固定分摊版本、退款，防止与工时重复分摊。逐客户逐周期分别展示获客前后贡献；贡献须为正，未知费用不填零 |
| 可持续字段与容量 | 运营及字段审阅负责人确认续购周期仍有有效许可、人员、响应和调用预算；实际人工持续计入成本 |

成本按币种分别报告，不能直接把 JPY 与 USD 等相加；需要换算时保留汇率和日期。贡献使用已出账金额，或已确认用量与价格的可解释保守上界；仍有未量化费用则未验证。A05 的本地输入声明和已知小计不能自动证明真实账目完整或正贡献。

现有计算口径为：获客前贡献 = 实收净额 − API − 人工 − 客服 − 固定分摊；获客后再减渠道成本。贡献不是全公司利润。无可靠客户基线工时只报告实际分钟，不宣称节省比例。每周分别记录意向、签约、付款、交付、验收、续购、退款，不用账户数、发布数或点击替代履约与收入。

## 5. GR：自然复用与消费者分支独立取证

依据：[M01 自然复用测量](./feature-module-designs.md#m01-商业漏斗与自然复用测量) · [C 阶段分支条件](./next-feature-roadmap.md#c按证据选择产品化范围)。

两批独立、合格且同意测量的设备各 ≥10，首个观察到的合格完成已满 7×24h，R7 各 ≥30%，才达到继续研究的临时标准。R7 为首完后 `[24h, 7×24h]` 内，在另一会话完成新分析或主动刷新已存计划的去重设备占比；首批次继续处理第二家、即时刷新、只打开首页或自动恢复不算。

测量负责人须保留 cohort／同意／版本、live 资格、研究来源、成熟度、会话、去重和排除口径。benchmark、任务、报酬、提醒研究及 audit/demo 不进入自然 cohort，资格或来源未知单列。设备清存储、跨设备和不同意测量的覆盖缺口须报告；设备数不叫用户数，不外推全体留存。

GR 不证明消费者付费。消费者产品化仍需 GQ、独立自然复用和**该消费者报价的实际付费证据**；业务客户付款不能替代。当前无两批真实成熟自然 cohort 的门槛证据，也无该消费者报价实付证据。

真实执行前，将拟做动作落到下表已有边界；缺项继续留待确认。工具、资料结构或 fixture 的批准标签均不是用户批准。

| 动作范围 | 执行前要明确的内容 | 当前未取得项 |
| --- | --- | --- |
| 参与者／客户招募与联络 | 对象、目标、联络动作、可使用的联系方式和同意范围 | 本包无外联授权或实际联络记录 |
| 真实资料处理与传输 | 字段、来源、用途、受控存储域、保留／清理责任、接收方；传输敏感资料及新权限须明确授权 | 实际任务范围、字段许可及处理批准待取得 |
| 上游付费调用／竞品购买 | provider、资源或 API 操作、现行官方计费依据／日期、一次性及每月固定金额、按量价格与最大调用量、最大暴露额、自动／人工停止条件、已有批准覆盖目标／动作／上限 | 尚无本轮真实比较或业务试点的调用额度与费用批准；不引用 fixture 价格 |
| 真实收款／开票 | 渠道、报价版本、履约／退款／客服、到账核对和商务记录保留 | 渠道、收费批准及真实交易待取得；不自动开通支付供应商 |
| 交付外发／公开阅读 | 收件对象、实际交付 revision、白名单与保留、发送授权；公开字段与私有导出权限分别审阅 | 无实际交付外发批准；M05-b 的真实传播需求与公开字段许可未取得 |
| 部署／公开发布 | 对应目标、成本批准、相关技术验收及发布检查表；上线按适用 release/pilot/public gate 执行 | 本包不提供部署或公开发布批准 |

现有每日硬上限继续有效：新截图 60、Qwen 60、OpenAI fallback 10、Places 搜索／详情各 90、Hot Pepper 60。试点可售容量需扣除核心流量及失败重试预算；这些全局上限不是本轮已批准调用次数。新增收费资源、供应商、计划、配额或超过已批准上限的动作须重新确认；执行后报告实际资源／请求和 provider 已显示的金额，未出账则明确标估算。

| B03 | A02；有行动报告需要 | 普通出站分类、目标核验和版本化匿名行动报告；不要求公开清单，也不代表合作成交 |
| B02 | B01；真实读者需求、写保护及 M02 | 可撤回／到期托管阅读链接；另外确认公开字段、权限、外发及适用发布门槛 |
| B04 | B03；合作资格／协议／持久层确认 | 单一合作方回传、去重、结算／扣回账本；协议与外部联调不能由 G1 推断 |
| C01 | GB；或消费者分支独立证据；事务／恢复 | 对应用途的账号、会话、资源权限；业务工作区权限须 GB，账号不自动触发消费者同步 |
| C02 | C01、A06；独立跨设备需求 | 可选私人资料同步、冲突、导出与删除；不作为业务自助的强依赖 |
| C03 | C01 的工作区权限、B05、GB | 已证明维护工作的客户自助、审阅、成员与审计；不强依赖 C02 |
| C04 | C02、B02；真实聚餐需求 | 私密协作邀请、投票、退出／撤销；GR 或业务续购不自动解锁社交 |
| C05 | A06；明确遗忘问题 | 手动日历导出；通知为独立范围及权限／费用决策 |
| C06 | C01、A05；对应报价实付／续购与贡献、收费批准 | 一种报价的事务权益账本、恢复、checkout 沙箱与回调；供应商调用另按费用批准 |
| C07 | C06；正式收费前完成 | 取消、退款、争议、权益与客服；工程完成不自动授权正式收费 |
| C08 | A06；GR 与实际整理需求 | 按需本机集合／标签及有界迁移；云同步独立决定 |
| D01 | C01；商家需求／身份数据；效果报告需 B04 | 受限商家认领与修订；身份核验及数据／外联授权独立取得 |
| D02 | Web 增量与入口流失；原生分支、费用及发布前提 | iOS 分享交接与真机验收；in-app Browser 不替代真实 iPhone 分享证据 |
| D03 | 独立访日客群需求、服务责任、数据／费用授权 | 独立服务规格、任务和成本；运营协助可用获批人工商务流程，自助收费才依赖 C06 |

GQ 不足时先修核心任务；G1 仅支持有边界的运营协助试点；GB 支持业务自助分支；GR 只支持消费者复用研究。业务有证据而消费弱则优先业务；两者都弱则调整任务／客群，停止新增账号、支付与社交范围。

## 8. 复核记录与 fixture 禁用规则

每次门槛复核保留：门槛／protocol 或 offer 版本、适用 revision、实际范围、责任人、受控证据引用、完整分母与缺口、成本／资料／执行批准覆盖、结论及本次选中的任务。原始材料留在对应受控研究／工作／商务存储域；公开文档只放可分享的摘要与引用，不放联系人、客户内容或付款凭据全文。

- synthetic 案例、虚构访谈／报价、影子权益、fixture 工作区、许可证据、操作者、验收和金额永远不能成为 GQ/G1/GB/GR 证据；不能修改模式、编号或标签后冒充真人输入。
- benchmark 的 `fixture_only`、商业研究的本地未核实声明、A05 的 `explicit_local_snapshot_unverified` 和 A12 的 `fixtureOnly: true` 只说明工程／计算边界。退出成功、数量达标或客户端声称批准都不能通过门槛。
- 本地输入能力不构成真实数据授权；人工验收不构成事实认证；自然 cohort 不能从 benchmark 记录复制。未知维持未知，未取得维持待取得。
- 门槛结论绑定冻结版本。研究后改变阈值、路线或范围需新版本，不得看结果后降低门槛；通过结论仅覆盖记录中选定分支，不自动授权其余任务、付费动作或发布。

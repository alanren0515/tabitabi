# 三个可开始的公开自测案例

准备日期：2026-10-03 JST。沿用仓库现有文字案例，并用 Codex in-app Browser 读取以下三个当前官方页面。这里只准备输入和核对依据，没有发起 Places／视觉识别、查看实时空席或提交预约；不新增人工 `confirmed` 记录，不表示 GQ 通过。执行时由你重新确认身份与关键规则，并填写 [自测记录](./self-test-record-template.md)。

这三例可用于 ST09、ST11–ST15，重复查看同一结果不必重新请求。真实文字核对仍需批准的调用额度；ST10 可由你截取官方店页作为第一张真实图片 smoke，之后再试公开 SNS 素材。官方页面截图不能冒充 Instagram／TikTok 识别已经验证。

## CASE-01：明确身份与预约入口

- 输入：`つるとんたん 六本木 東京都港区六本木7-8-6`
- 官方依据：[つるとんたん六本木](https://www.tsurutontan.co.jp/roppongi/)。本次页面显示六本木店及地址 `東京都港区六本木7丁目8-6`，并链接 [该店 TableCheck 入口](https://www.tablecheck.com/ja/shops/tsurutontan-roppongi/reserve)。只核对到链接存在，未打开空席／登录／最终确认页面。
- 预期：确认这家六本木店，而不是同品牌其他店或历史地址；入口存在不等于有空位或预约成立。先记录候选正确，再记录行动指向正确，两项分开。
- 截图准备：官网店名、地址和预约入口所在区域，裁掉无关内容；不要附账号、通知或任何已登录页面。
- 历史对应：`text-tsurutontan-roppongi-006`，原人工确认 2026-07-12。今日官网读取只支持准备预期，不能覆盖旧审计的设备证据。

## CASE-02：同品牌、附近不同分店

- 目标输入：`鳥貴族 渋谷井の頭通り店 東京都渋谷区宇田川町31-3`
- 官方依据：[鳥貴族 渋谷井の頭通り店](https://map.torikizoku.co.jp/detail/181/)。本次页面显示 `東京都渋谷区宇田川町３１-３ 第３田中ビル ３階`，下方同时列出附近其他分店。
- 预期：店名含“渋谷井の頭通り店”，地址应对应 31-3／第3田中ビル3階；不能把页面下方附近店铺的地址或规则借给目标店。先试 `鳥貴族 渋谷` 观察模糊线索，再补足目标分店和地址；两次搜索都计调用，不因为是同一案例就免费。
- 纠错检查：候选不对时点“不是这家”或返回修改线索，确认新结果和保存计划不会仍绑定错误分店。不要为了测试故意提交真实错误预约。
- 截图准备：保留完整分店名与地址；如截到附近店铺列表，明确标出你要核对的目标，观察产品是否让你主动选择。
- 历史对应：`text-torikizoku-shibuya-inokashira-017`，原人工确认 2026-07-13。

## CASE-03：目标店不可预约，别借用其他店规则

- 输入：`串かつだるま 新世界総本店 大阪市浪速区恵美須東2-3-9`
- 官方依据：[だるま 新世界総本店](https://www.kushikatu-daruma.com/location/shinsekai)。本次页面在目标店说明与资料表标记预约不可，地址为 `大阪市浪速区恵美須東2-3-9`；同页还含其他分店预约规则及跳往其他店的预约入口。
- 预期：结果应尊重目标店不可预约的当前官方说明，不把同页其他分店入口说成目标店可预约；到店、电话或导航仍不等于预约成功。若产品无法可靠核实，应明确未知而不是保证能预约。
- 截图准备：先截目标店名、地址和预约规则区域；再在额度允许时用包含多店规则的页面区域观察归属能力。两张图片是两个真实识别输入，分别占用批准额度。
- 历史对应：`text-kushikatsu-daruma-shinsekai-014`，原人工确认 2026-07-12。历史曾出现借用下方难波店规则的问题，本例保留这个回归重点，不预填通过。

## 如何少量测试

先执行供应商零调用的 ST01–ST08，再按已批额度选择 CASE-01 做一条文字全流程，复用其结果看来源时间、入口与保存。之后按额度执行分店纠错、不可预约边界和一张自行裁净的真实图片；多店队列可以先只导入三行、暂停和刷新，再主动核对获批的一项，不自动处理整批。

如果某官网打不开、门店资料变化或与结果冲突，保留未知并记录该匿名 CASE 编号、版本和核对时间，不用本文件的旧信息覆盖当天来源。空席、临时营业、价格与预约规则仍需实际来源确认。本包不含原始 SNS 图片、私人信息或第三方完整快照。

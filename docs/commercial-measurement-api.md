# A02/A03：v2 事件接收、客户端与研究状态

2026-10-02 完成后端实现；2026-10-03 完成 A03 客户端接入、可选同意、会话、有界重试与自然 R7 离线汇总。v1 保留给原 pilot/release 口径，v2 独立采集；默认不创建设备研究标识。本文不表示已部署。

## 接口与权限

三个接口均沿用 pilot／public／local 的访问模式、审计访问保护及事件速率限制；生产环境既未配置 pilot 也未明确 public 时拒绝访问。响应 `Cache-Control: no-store`，没有公共日志读取接口。

| POST 路径 | 请求／返回要点 |
| --- | --- |
| `/api/measurement-flows` | 请求 kind=analysis/review、sessionId、analysis 的 inputType，可选 batchId。返回服务器生成的 flowId、随机 token、analysisRunId 或 interactionId、expiresAt |
| `/api/events` | v2 契约字段及可选 research 对象。202 返回 accepted、duplicate、researchLinked；明确 v1 或不带版本仍走旧日志；其他版本拒绝 |
| `/api/research-consent` | consentVersion=research-v1、state=accepted/declined/revoked；接受／撤销附 deviceId 与随机 token。初次接受另附 requestedAt |

关联分析或复核时，事件以及提取／搜索／详情 API 都带 `X-Measurement-Flow` 和 `X-Measurement-Token`。它们是短期测量能力，不是用户账号。sessionId、batchId 必须与注册值一致；analysisRunId/interactionId 必须是服务器给该流程签发的编号，不能借用另一流程。app_visit 仅有 sessionId，sourceMode 为 unknown，不作为完成证明。

流程 token 由服务器生成 32 个随机字节，研究 token 由客户端生成 32 个随机字节，均为 43 位 base64url 文本。设备及会话编号使用随机 UUID v4。token 仅在请求／注册响应内使用，不能进入 URL、普通事件、日志或分析输出；持久状态只保存摘要。研究凭据与流程凭据用途分离。

## 服务端流程校核

分析输入到达提取处理器后记录真实尝试，输入／搜索／详情成功另记录成功阶段。live 表示服务端观察到的真实流程尝试，不等于成功、准确、有位或预约成立。失败输入仍进入合格漏斗分母，不能只保留最终成功流程。

analysis_completed 必须已有成功的输入、搜索和详情；review_completed 只要求本次复核的详情成功。候选事件要求搜索成功。顺序错误或输入类型不一致保持 unknown；客户端自报 live、releaseRevision、自然渠道不能提供资格。webpage 是原始入口类型；餐厅文字附普通或预约链接可经文本解析成功形成输入证据，纯链接只记录尝试，仍需网页提取或可用文字线索才能满足完成资格。截图补充文字不携带截图输入能力。文本名称可由本地解析器形成真实输入证据，截图／网页／搜索／详情的观察点附在相应实际处理器中；无额外上游请求。

demo 标志和 audit 流量只允许向排除方向变化。一旦某阶段声明 demo，该流程已有及后续记录全部保持 demo；重发相同事件也可补充这一降级信号。审核来源默认 unknown，benchmark／任务／报酬／提醒提示仅用于排除，不能由浏览器宣称 natural 就升级。渠道由服务端 `measurement-campaigns.mjs` 白名单映射；当前登记表为空，访问一律不推定为 natural。登记真实渠道前需要明确获客来源与研究排除条件。URL 仅接受 1–40 位小写短码，读取后移出地址栏，不读取 referrer。

流程写入有效期为 30 分钟，部署 revision 变化也使新观察／事件失效；已持久接受的事件在其 30 天保留期内仍可凭原流程能力取得重复回执，归属原 revision。过期或测量失败时不应为了补日志重跑识别或调用付费 API；下一次用户主动操作建立新流程。

## 幂等与存储

v2 状态位于受保护且被 Git 忽略的 `data/commercial-state.json`，与 `data/events.jsonl` 完全分开。现有 pilot/release 指标只读原日志，本轮不更改其阈值或资格。

事件、幂等摘要、流程事实、同意状态和研究关联在同一次串行事务中更新：临时文件权限 0600、文件同步、原子重命名及目录同步。重发相同 eventId 和规范化事件返回 duplicate=true；同 eventId 内容冲突返回 409，不能覆盖原事件。研究凭据不参与事件正文摘要，撤销后的重发不会重新关联研究设备。

原子状态面向当前一个 Node 进程／一个 Machine；同进程同路径实例共用队列。它不是跨进程数据库，启动多个写入进程前必须更换为支持事务和锁的持久层。默认最多 5,000 条未到期事件、10,000 个流程、5,000 个同意／关闭标记，文件最多 10 MiB。满容量返回 503，不提前驱逐未到期幂等记录。研究关联最多随事件数量增长。

状态文件损坏或写入失败时测量请求返回 503，不重建空文件伪装成功。核心解析／餐厅请求继续返回实际结果，观察失败只记录固定错误码，不重复付费请求。处理存储故障前保留原文件，不能删除状态来绕过去重。

## 研究同意、到期与撤销

接受需要明确版本、随机 deviceId、随机研究 token 和与服务器相差不超过 5 分钟的 requestedAt。服务端以首次接受时间设置 30 天到期；相同凭据重试不会延长。只有最新 accepted 状态可产生独立 eventId→deviceId 关联，商业事件正文不保存 deviceId。

拒绝不需要设备标识，也不创建设备记录。已有接受者退出时发送 revoked；服务器原子删除该授权的全部研究关联及可识别设备记录，只留下不含 deviceId 的能力摘要关闭标记，用于阻止延迟的 accepted 请求重新注册。撤销即使先于接受到达也会阻止乱序接受；撤销前已接受的事件重发不会补回关联。重新自愿参加时使用新设备编号及新研究 token，不自动续期。

到期后立即停止新关联。每次状态操作、进程启动以及运行期间每 5 分钟执行清理；机器停止时不运行定时器，恢复后在受理请求前执行清理。已到期接受记录转为无 deviceId 的关闭标记，研究关联删除；关闭标记从到期／撤销起最多保留 30 天。旧接受请求即使在标记清理后重放，也会因初次请求时间超限而被拒绝。该最小防重放摘要不含原设备编号或研究明细。

A03 可生成仅含数量／比例的离线汇总，不含设备、事件、会话或授权编号。输出仍仅供内部分析，不构成严格匿名保证；不能承诺按个人回删已经导出的汇总。API 时间依据服务器，客户端时钟偏差导致初次接受失败时应提示校正并重新明确确认，不静默加入研究。

## 验收与已知边界

自动覆盖并发重发、跨实例／重启、冲突、源资格伪造、复核隔离、真实失败分母、混合 demo／audit、旧 revision、30 分钟／30 天边界、同意重试不延期、先撤销后接受、撤销后重发、到期清理、容量与损坏、敏感字段白名单。

实际本机 HTTP 测试覆盖 pilot 拒绝、完整提取→搜索→详情观察、拒绝提前完成、并发重复、重启恢复、研究撤销、旧反馈兼容、私有状态不能静态读取，以及存储损坏时核心解析继续工作。供应商 fetch 使用本地固定响应，其他外部请求拒绝，实际供应商网络调用为 0。

A02 阶段 467 项全量测试通过；A03 最终验证及浏览器证据见 [实施记录](./implementation-progress.md)。此证据不替代真实供应商回归、真实 iOS Safari、真人 GQ 或公开发布验收。


## A03 客户端与统计使用

- `/privacy` 提供 JA／EN／ZH-CN 可选研究说明。明确参加后才产生本机随机设备编号与研究能力；服务端确认前保持未关联。拒绝不影响功能。
- 会话保存在 sessionStorage，空闲 30 分钟轮换；每个分析／复核冻结自己的会话和服务器流程能力。事件仅用内存队列，最多32条，每条至多尝试2次，重用 eventId；网络请求超时1.5秒。测量失败不重跑业务 API。核心分析入口注册最多等待1.5秒。
- 研究凭据单独在 localStorage 保留，跨标签页读取最新状态。撤销立即停止关联；请求未送达则只保留重试凭据，页面明确显示待重试。启动、恢复联网或用户点击可重试撤销；参加请求只由明确操作重试，不自动续期。
- 清除本机数据先尝试撤销，随后清除计划、队列、历史、设置与测量会话。撤销失败的最小凭据仍保留，直到请求被服务器确认；页面不把待撤销显示为成功。若邀请权限也被清除，需要重新输入邀请后重试。
- `reviewIntent=saved_plan_refresh` 表示用户主动复核自己的计划；`history_open`、`automatic`、`unknown` 不进入自然复用。复核不创建新的 analysis_completed。
- 新输入及待办队列保留 batchId；同一队列条目被重复加入时保留最早批次；旧条目来源未知，用 batchOriginKnown=false 排除自然复用。A07 暂停、草稿恢复和批次终态已完成；示例体验与原任务隔离，详见 [本机存储契约](./local-task-storage.md) 和 [全面审核](./a-stage-comprehensive-audit-2026-10-05.md)。
- 主分析、输入、线索、候选、确认、完成／失败、主动操作和结果页保存镜像到 v2；历史复核、主动计划复核独立记录。app_visit 与自由文本反馈继续原 v1；不把访问当完成，不把介绍页点击当预约能力。

运行 `npm run commercial:summary` 默认只读取合成 fixture，输出 `fixture_only`、`realWorldEvidence=false`。检查获准使用的本地状态快照须显式指定全部参数：

```sh
node scripts/summarize-commercial.mjs --input PATH --as-of ISO_TIMESTAMP --revision FULL_SHA
```

汇总按目标 revision 的 live/product 流程去重，输入与完成取交集；所有排除和零分母显式输出。自然 R7 从同意后的首次合格分析完成起算，满7天进入分母；回访必须另一会话，在闭区间24小时至7天完成新分析或主动计划复核，首批次续做除外。只统计仍有效且覆盖整个观察窗的同意设备；撤销／到期关联已删除时不能补做历史回溯。

渠道、来源、输入类型和设备类型切片少于5个唯一同意设备时隐藏。当前未推断设备类型，保持 unknown。总体和成熟分母用于内部诊断，不能对外发布为客户报告；没有真实来源登记与成熟样本时，fixture 不构成真实 R7、市场需求或商业前景证据。

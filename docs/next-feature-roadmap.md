## 1. 综合结论与本轮目标

下一轮主线确定为：**让日本餐厅的核对更准确、更省事，再验证多家餐厅的持续维护是否值得付费。** 消费者端保留轻量核对入口；优先研究多账号餐饮营销代理商、美食媒体及高频维护者。这里确定的是验证顺序，尚未证明业务需求和收入。

三份报告合并后的取舍：

| 依据 | 形成的产品决定 |
| --- | --- |
| 原商业模式：自然复用、明确价格、单位成本尚待验证 | 保留 M01/M02/M04；消费者问卷、业务报价、实付及续购分层 |
| 原功能设计：已有识别、分店确认、计划、队列与安全入口 | 复用现有流程；不重建引擎；保留各模块 ID 和权限／费用边界 |
| 竞品报告：截图转地点、共享地图、行程和卖指南已有供给 | 缩小 M03；M05/M07 聚焦核对交付与维护，通用社交和收藏扩建后置 |
| 竞品报告：可靠性仍未实测，业务维护的数据与人工成本未知 | 新增 M15 核对摘要／复核任务、M16 同案例评估；付款和续购决定自助产品化 |

规格编写阶段的完成证据是可实施的规格及测试／测量定义。当前 A 工程验收见实施记录；后续仍须取得对应真实任务／客户证据，不能用文档或 mock 结果宣布商业成立。当前未读取最新 Fly 生产指标，不把旧审计计数当当前留存或收入。

## 2. 下一版的具体功能范围

首个开发批次为 **M01、M02-a、M03-a、M04、M15-a、M16**。M15-b 的模型可先用 fixture 准备，实际业务工作区在 B 阶段启用。

| 用户／运营者能做什么 | 首版交付 | 本轮取舍 |
| --- | --- | --- |
| 更快完成一次可信核对 | 结果首屏显示门店／分店、行动、必要限制、核对时间含义；冲突就近阻断，证据按需展开 | 不跳过人工分店确认，不靠隐藏风险减少步骤 |
| 修改错误而不重做全部流程 | 返回修改保留线索和已提取内容；重新选分店只失效受影响结果；字段级问题可记录 | 不自动把用户纠错当已核验事实 |
| 暂停并继续多餐厅任务 | 当前项／待处理／失败状态、进度和主动逐店恢复；已有本机计划可搜、可记备注 | 集合、多标签、云同步不作为首批必需；不自动跑整批 |
| 知道结果是否需要再核对 | 区分本次生成时间、实际来源获取时间、复核到期／冲突；保存最小核对元数据 | 不把缓存读取当刚抓到来源，不承诺实时营业／空席 |
| 比较产品是否真有增量 | 本地同案例比较工具，包含全任务分母、未知／弃权／超时、正确行动和完整任务耗时 | 不把 API 耗时或出站点击当用户任务成功 |
| 看清成本和需求 | 上游尝试归属、人工／维护工时、版本化报价和信号报告 | 不收费、不显示虚构套餐余额，不自动优化价格 |
| 交付少量餐厅维护服务（B） | 私有维护任务、逐字段证据、客户审阅清单、验收和周期报告 | 先运营协助；客户登录、自助后台、公开传播及自动支付均有后续条件 |

## 5. 交付阶段与分支门槛

### A：核心结果与测量

交付上述六个首批模块切片。先冻结 M16 协议及可复现旧版本，再改 M15-a；真人比较须保留旧版 baseline、新版 candidate 和一条预定主要替代路线的完整记录。事件和成本可以并行准备，访谈不必等待功能齐全。默认邀请制；不新增供应商、收费、批量后台轮询或公开访问。

**GQ 质量门槛（探索标准）**：10–15 位目标用户、至少 30 个去重案例，配比、时间上限和设备可用性冻结。主替代路线默认“Maps＋官网／预约平台”，预定一种一致操作路径；其他直接竞品仅作次级比较，不能选择最有利对象判通过。新版相对旧版及主替代路线的全任务正确完成率、可行动解决率均不下降，且无新增关键误导；增量再相对主替代路线满足其一：成功任务中位耗时降低 ≥25%，或难例关键错误减少且常规成功任务中位耗时增加 ≤10%。三路线须对同一有效案例集完整覆盖，缺记录为证据不足；未知／弃权／超时留分母，任务分配量至少为案例数×3，不把重复任务当独立案例。小样本只支持探索判断。完整口径见 M16。

GQ 数据缺失或不通过时，优先修复核心任务；不因完成埋点开启更多功能。M15-b/M05-a 的 fixture 可提前准备，实际业务试点仍需下面条件。

### B：运营协助的餐厅维护试点

**G1 开始条件**：GQ 有足够可复核的通过证据；访谈 5–8 位实际维护者，至少 2 位接受同一版本的明确范围／价格并提供真实任务；限定字段／来源、更新频率、交付责任、人工容量、数据处理及调用费用可执行。G1 是意向信号，不是订单或付费转化。

先交付 M15-b、M05-a、M07-a；M06-a 按行动报告需要加入。首轮最多 3 个客户工作区、每客户最多 20 个餐厅条目，按任务主动逐店核对；不能把额度当可自动调用次数。公开清单 M05-b、佣金 M06-b 都不是收费维护试点的必要条件。

真实服务收费可以经单独批准的人工商务收款／开票渠道执行，不要求先建设 M08/M11；因此不会出现“先做支付才能验证支付”的依赖循环。尚未选择收款渠道，报价、联络、收费、传递客户内容、付费调用和交付外发仍按已有授权边界分别执行。本规格不自动执行这些动作。

**GB 自助产品化条件**：至少 2 位客户各完成首次周期及至少一次按该价格付费续购周期的交付和验收；逐客户、逐已完成周期核算已收净额与 API、重复核验人工、客服及渠道，贡献均为正，并单列获客前后贡献。续购仅到账、未履约或未验收不能通过；成本使用已出账金额，或已确认用量和价格的可解释保守上界，仍有未量化费用则未验证。字段／权限／容量须可持续。每周分别记录意向、签约、付款、交付、验收、续购、退款。

### C：按证据选择产品化范围

- **业务分支**：GB → M08 的工作区权限 → M07-b → 经批准的 M11。只为已证明的维护工作减少交付成本，消费者全量同步不是必需依赖。
- **消费者分支**：GQ＋独立自然复用证据＋该消费者报价的实际付费证据 → 按需 M03-b/M08 → 经批准的 M11。业务客户付款不能代替消费者付费；M09/M10 各自还需任务证据。
- **GR 自然复用探索条件**：两批独立的合格、同意测量设备各 ≥10，首完已满 7 天，R7 各 ≥30% 可作为继续研究的临时标准。它不是行业基准或统计证明；benchmark／任务／报酬／提醒研究不进入自然 cohort，数据不足为未知。
- 质量不足先修质量；业务有证据而消费弱则优先业务；两者都弱则调整任务／客群，停止新增账号、支付和社交范围。

当前真实输入缺口、责任与分支解锁见 [下一阶段进入包](./next-stage-entry-pack.md)，真人验证准备见 [验证执行手册](./real-validation-runbook.md)。GQ、G1、GB、GR 均为开发投入决策，不替代安全测试、成本批准和公开发布检查表。无当前测量基线，阈值沿用竞品报告中的探索假设；研究前冻结，改变须新 protocolVersion，不能看结果后降低门槛。

### D：独立扩展

M12/M13/M14 各自定义客户、供给、责任、成本和验收。国际化优先验证海外客户使用日本餐厅服务；跨国餐厅覆盖另有本地供给和规则成本，不作为翻译界面的附带功能。

## 7. 完成标准与验收记录

- 首批技术验收：原分店确认、风险和预算行为不弱化；来源时间不混用；返回修改／批次恢复不重复识别；旧数据不丢失、未知字段不泄漏；错误／离线／额度耗尽保留输入。
- 测量验收：完整任务计时与确认后 API 耗时分开；失败保留分母；研究样本与自然流量隔离；费用缺失不显示为 0；意向、实付、验收和续购能独立报告。
- 业务验收：只交付许可字段；任务 unresolved 可解释；修改已有发布结论需重新审阅；重复维护和失败工时计成本；客户验收不提高事实可信度。
- UI 实施使用 Codex in-app Browser 验证日文手机流程、键盘及空／错／离线状态；真实 iOS 证据单列。文档和离线工具不要求无关产品浏览器旅程。
- 沿用 Node 测试及现有 eval，只补状态、迁移、权限、计算等必要测试；商业比较工具不调用竞品 API、不默认调用付费供应商。
- 每项记录 revision、实现切片、相关自动／浏览器证据、实际研究条件、未实现项和发布状态。旧 [产品审核计划](./product-audit-and-implementation-plan.md) 的问题先按当前实现复现，历史结论不直接当未修缺陷。

## 8. 共同边界与暂缓范围

保持日本国内、日语优先；正式界面日／英／简中文案及日文事实原文规则不变。消费者首次核对无账号门槛。预算、身份和上线要求继续适用。

- 本地实现已按用户后续开发指令推进；本规格不自动授权供应商付费联调、客户联络、收款、交付外发或部署，不新增 Machine、Volume、域名和外部权限。
- 每日硬上限不变：新截图 60、Qwen 60、OpenAI fallback 10、Places 搜索／详情各 90、Hot Pepper 60。服务报价须覆盖既有容量，不能售卖无上限或持续自动核对。
- 不默认开发全量 SNS 抓取、自动预约／电话、空席预测、评分数据库、付费事实排序、复杂地图社区或国际餐厅全覆盖。
- 数据字段用途／保留按来源逐项确认；Place ID 和自写资料与 API 详情分开。工作区、研究数据、事件及收款凭据使用独立存储域与保留规则。
- 真正权益／订单账本须唯一约束、事务及恢复能力；先评估现有 Volume，不默认新增托管数据库。供应商价格／费用在具体动作前重新核实并按项目批准边界执行。
- 公开发布继续遵循 [公开发布检查表](./formal-public-release-checklist.md)、[人工审计](./manual-audit.md)、[试点手册](./pilot-runbook.md) 和 [事故处理](./security-incident-response.md)。

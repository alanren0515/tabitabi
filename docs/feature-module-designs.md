## 0. 下一版设计决定

消费者主流程继续是“线索 → 修正 → 确认分店 → 可信行动”。首批改善结果理解、纠错、任务恢复，并测量相对已有免费路径的增量。业务主流程新增“约定维护范围 → 私有复核任务 → 逐店处理 → 客户审阅 → 验收／周期成本 → 续购”，先由运营协助，不先建设通用地图社区或完整自助 SaaS。

| 设计取舍 | 下一版具体设计 |
| --- | --- |
| 核对价值高于功能数量 | M15-a 首屏是一家店、一个主行动、相关限制；证据可展开，关键冲突始终可见 |
| 入口需保持可理解 | 截图主入口，店名／链接次入口；动态帖无法读取时就近要求补图／店名，不伪装已读帖子 |
| 集合功能不是默认竞争方向 | M03-a 只补任务进度、备注／搜索、恢复；M03-b 集合／标签由需求触发 |
| 维护价值先用真实工作验证 | M15-b 记录字段、来源时间、待办和人工工时；M05-a 交付私有清单，M07-a 报告实际维护工作 |
| 公开流量和佣金不是维护服务前提 | M05-b 可选发布，M06-b 有合作才归因；M07-a 不依赖两者 |
| 商业证据不可互换 | M04 分开报价意向、付款、交付验收和续购；早期获批人工收款不必等待 M11 自动支付 |

### 决策指标

| 指标／用途 | 定义与来源 | 限制及负责角色 |
| --- | --- | --- |
| 正确完成与任务效率：判断核心增量 | M16 中人工真值一致的终结任务／全部有效分配任务；成功任务的从任务开始到正确终结的中位耗时另列 | 失败／未知／弃权仍报告；API 耗时不是完整任务耗时。产品负责人复核真值，工具确定性计算 |
| 维护工时：判断服务能否节省工作 | 客户同范围基线分钟与实际交付总人工分钟分别除以验收条目数；同时显示任务总量、unresolved 和返工 | 包含首次／重复核验、沟通、失败和返工；基线为客户自报时注明。运营者记录，客户审阅 |
| 实付续购与客户贡献：决定自助产品化 | 报价版本下完成实付、验收及再次实付的客户数；已收净额减归属 API、人工、客服及渠道成本 | 意向不计，退款更正，费用缺失为未验证；贡献不称全公司利润。商务记录、运营对账 |

首要质量保护为可行动案例解决率不下降、无新增关键误导；成本保护为现有硬预算和不售卖无法交付的容量。R7 用于消费者分支诊断，预约出站用于行动诊断，均不是维护业务的收入证明。当前没有实测基线，数值门槛是竞品报告中的探索假设；实验前冻结版本，不据结果回调目标。

## 1. 设计共同前提

### 产品与交互

- 日本国内日语用户为核心；界面正式文案继续维护日／英／简中，店名、地址、证据和预约条款保留来源语言。
- 首次核对不要求注册。信息确认、风险提示和来源不因套餐隐藏；付费权益围绕用量、整理、协作和工作流。
- 首页继续以截图核对为主任务。资料夹作为次级导航，内部维护工具不放进普通用户首页；报价不挤占核心输入流程。
- 用户身份与门店身份分开：登录成功不等于门店已确认；创作者推荐不等于预约可用；商家认领不等于所有提交内容已核验。
- 正确分店与可信行动始终优先于佣金。广告或合作说明必须可见，不改写事实、不伪装成官方认证。
- 打开页面、恢复后台标签或发布清单不自动触发付费核对。带上游调用的操作由用户明确点击，并受服务端预算和滥用控制约束。

### 数据与证据

- 截图不落盘；第三方实时详情和评分不加入永久餐厅数据库。持久化 Place ID、用户自写字段和必要的状态；可保留的第三方字段须按当时许可逐项确认。
- 本机计划、内部工作记录、客户交付、对外发布及后续云资料分开投影。字段登记包含来源、用途、保留、导出和公开许可，默认未评估字段不保存／导出；用户确认 API 内容不自动使其成为自写资料。
- 新分析沿用 `analysisRunId`；再次核对已有计划使用独立 `interactionId`，不伪造新的首次分析。事件另有 `eventId` 用于网络重发去重，以及不活动 30 分钟后更换的短期 `sessionId` 用于区分访问会话。
- 商业报告排除 audit、demo、任何混合演示流程、旧 schema 和不满足所属版本条件的事件。跨版本趋势必须显式展示版本和变化，不能混入同版本发布 gate。
- 未知、未配置、未回传、没有样本和明确的零分开表示。用户自报结果、合作方确认结果、可结算结果、实际收款分开统计。
- 分析日志默认 30 天，聚合报告建议最多 90 天；新增保留周期、会话、云资料和订单保留策略在启用前审阅，不能把现有日志策略直接套用于会计账本。

### 成本与权限

- 功能完成只授权到其原有范围。账号／通知／支付供应商、敏感数据传输、付费调用和公开发布继续遵循项目批准边界。
- 维持当前单实例及全局硬预算。匿名浏览器配额仅是体验约束，不能作为防止分布式滥用或多设备刷量的唯一手段。
- 现有审计工作台只用于本地／受控 LAN 审计。新账号、创作者和运营权限不能复用共享 pilot code 或现有审计 token。
- 草稿和 mock 本地开发不需要先开通付费服务。真实供应商联调和上线证据单独计划，不用示例冒充完成。

## 2. 页面与权限结构

```text
主产品：核对餐厅 → 修正线索 → 确认分店 → 结果／可信行动
        └ 本机任务：想去计划／待核对／最近核对 → 进度／备注／搜索
        └ 自愿需求反馈：明确权益／价格 → 意向（收费获批后另有结算）
        └ 设置：语言／本机数据／可选账号／隐私选择

清单阅读：/lists/:readToken → 作者／自写清单 → 单店按需核对 → 外部行动
客户：/workspace → 维护任务／交付审阅／工作报告（自助阶段）
协作：/groups/:groupId → 受邀清单／投票／计划（后续阶段）
运营：本地维护工具 → 范围／待复核／纠错／交付／工时与付款证据引用
评估：本地 benchmark 工具 → 冻结协议／真值／比较记录／完整分母报告
```

路径为信息架构提议，不承诺现在可访问。B 阶段工作台只供内部运营，客户在受控审阅会话或经授权交付中确认；不提供客户公网写入。M05-b 托管阅读路径是可选范围；受保护清单不提前生成含私人标题的社交预览。

| 角色 | 允许 | 默认不允许 |
| --- | --- | --- |
| 匿名／pilot 用户 | 核对、整理本机资料、填写反馈 | 修改云端清单、浏览他人私密计划 |
| 清单读者 | 读取被发布的字段、按需核对、保存副本 | 查看作者私人备注、日期／人数、收入、编辑清单 |
| 账号所有者 | 管理自己的云资料、导出／删除、建立 workspace | 访问其他 workspace |
| 创作者 owner／editor | owner 管理成员／发布；editor 维护获授权草稿 | editor 管理付款、成员或他人 workspace |
| 创作者 analyst | 读取该 workspace 的聚合报告 | 查看读者原始搜索、个人画像、截图或订单个人信息 |
| 协作成员 | 查看被邀请清单、投自己的票 | 管理他人账号、编辑未授权集合 |
| 商家成员 | 提交获认领门店的修订、读自身报告 | 覆盖核验结论、购买事实排序 |
| 运营者 | 按职责处理内容、合作、异常和删除 | 在日常商业报表中读取截图、秘密、完整付款信息 |

| `PublishedList` | UUID、workspaceId、用户自写标题／介绍、公开 entries、revision、状态 | 与私人计划独立；撤回后读接口不能返回历史内容 |
| `PublicEntry` | Place ID、作者自写或有公开许可的名称／区域／介绍／来源链接 | API 名称改名为“作者确认”不能绕过许可；不含原截图、私人计划、评分快照 |
| `OutboundVisit` | 随机 visitId、list／entry 引用、provider、目标引用、关联有效期、披露版本 | 有效期按协议；不把账号／邮箱写进跳转 URL |
| `ConversionRecord` | provider conversionId、visitId、状态历史、人数／净额（仅协议许可）、证据引用 | 合作协议和保留策略决定；不能用分析日志充当账本 |
| `PriceSignal` | offerVersion、价格币种／周期、选择枚举、来源上下文 | 默认匿名；候补联系信息进入分离受保护存储 |
| `ManagedWorkspace` | 随机 ID、运营责任人引用、客户自定标签、状态、revision、操作记录 | B 阶段启用；无客户登录／成员权限；联系信息另存 |
| `Account/WorkspaceMembership` | 随机账号 ID、最小登录凭证、workspaceId、role、状态、revision | C 阶段启用；可认领已有工作区；会话／个人资料不写事件日志 |
| `Entitlement/UsageLedger` | subjectId、planVersion、operationId、额度／周期、预留和扣减 | 服务端原子变更；登录、支付失败或清本机不能重置 |
| `Order` | provider orderId、账号引用、报价版本、金额币种、状态、幂等键 | 卡片由支付方托管；退款／争议和删除规则上线前确定 |

以上不是数据库选型。A 阶段沿用现有模块和有界 JSONL，套餐只做影子计数和状态 fixture；分析日志不能充当真实权益账本。B 阶段少量可变工作对象可用服务端串行写入、版本校验和原子替换。合作成交账本、账号、真实权益及自动订单启用前须有支持唯一约束、事务和备份恢复的持久层；先评估现有 Volume 内的方案，不默认引入新托管数据库或扩容。合作账本可以先于账号启用，但不能先于该持久层。

人工付款证据使用私有受保护工作记录及唯一记录 ID、revision 和操作记录，不依赖 30 天分析日志裁剪；不是可扣费／发权益的支付账本。删除／恢复策略在真实收费前确定。B 阶段内部工具开发可用 fixture，未具备工作区读写与恢复保护时不能录入真实客户资料。

## M01. 商业漏斗与自然复用测量

**目标与基线。** 判断哪里流失、谁主动回来、哪种渠道带来有效使用。已有一次性运行 ID、流程去重、反馈、版本隔离和无用户标识的 7 日回访下界；后者不能解释为真实用户留存。

**首版流程。**

1. 入口接收注册过的短 `campaignId`，映射为渠道枚举；剥离未知参数，不保存完整 referrer。来源未知就是未知，不猜成自然渠道。
2. 分析阶段沿用原流程，新增开始／失败阶段、行动能力类型和资料夹互动。客户端上报经 schema 校验；live／demo 与版本由服务端流程信息校核，不能仅相信浏览器自报。
3. 如用户自愿参加回访研究，展示简短同意：“利用状況の調査に協力する”；不选仍可用。仅此 cohort 生成有期限的第一方随机设备标识，不使用指纹、不跨站追踪。
4. 用户在另一次会话且至少间隔 24 小时后完成新分析或主动刷新自己的计划，记录自然有效复用；首个批次继续处理第二家、即时重复刷新、只打开首页或自动恢复页面都不算。
5. 运营工具输出按渠道、研究来源、输入类型、设备粗分类和版本的聚合。对客户开放细分须至少有 5 个已同意研究的去重设备支持，并标注设备数；独立数量未知不以事件数补足门槛，非同意读者只进入运营粗总量。

**口径契约。**

| 指标 | 定义 |
| --- | --- |
| 分析完成率 | 合格 live 完成运行数 / 合格 live 输入运行数；继承现有口径 |
| 行动率 | 有任一主要行动的完成运行数 / 完成运行数；继承现有口径 |
| 预约出站率 | 打开直接预约／平台管理预约流程的完成运行数 / 完成运行数；电话、地图、普通店铺页和搜索入口另计 |
| R7 自然有效复用 | 同意研究且首个观察到的完成流程已满 7×24h 的设备中，在首完后 [24h, 7×24h] 内于另一会话完成新分析或主动刷新已存计划的设备占比；排除首批次续做 |
| 渠道质量 | 各渠道的完成、预约出站、有效复用和反馈分别显示，不压成单一虚构评分 |
| 自报预约成功 | 回答 succeeded 的有效反馈运行数及反馈分母；不计入合作确认成交 |

R7 的锚点是同意后首个观察到的合格完成，不宣称用户生命周期首次使用；会话边界为本站不活动 30 分钟。24 小时是避免首次连续任务混淆的预定测量规则，不是行业留存标准。排除 audit／demo 和有任务／报酬／提醒的研究 cohort；资格或研究来源未知时单列，不强行归为自然。到期未成熟 cohort 不进分母，同设备重复行为只计一次。设备清存储、跨设备和不参加测量造成覆盖不足，报告标注；只代表同意者，不外推全体用户。当前回访下界指标保留独立名称。

**状态、数据与接口。** `consent=not_asked/accepted/declined/revoked`；事件 `pending/accepted/rejected`。A02 已增强 `POST /api/events`，新增受保护的 `POST /api/measurement-flows`、`POST /api/research-consent`；A03 已接入客户端及本地 `commercial:summary`，尚未部署；不开放匿名下载生产日志。eventId 持久去重 30 天；研究 deviceId 到期自动停止关联。撤销关闭后续标识使用，并删除可关联研究记录及尚未固化的 cohort 明细；不可反推个人的已生成匿名聚合不承诺逐条回删。实际后端权限、容量、单进程持久性及清理时机见 [A02 接口说明](./commercial-measurement-api.md)。

**异常。** 断网仅有界重试，不阻止主流程；撤销后不重发旧关联事件。无法确认来源、身份或 live 资格时进入 unknown／excluded。审计和 demo 排除以整次流程为准。

**验收。** 同事件重发一次计一次；混合演示全排除；0 分母返回 null；同会话第二家和次日恢复首批次不计自然复用，次日另一会话主动新分析计入；24 小时／7 天边界、成熟 cohort、提醒研究排除有确定性 fixture；不同版本指标不能进入现有 release gate；单设备多次阅读仍不满足客户细分阈值，数量未知不按事件数推人数；拒绝研究仍完成全部核心功能。

**依赖／指标。** 独立开始；数据/隐私 schema 先落地。观察测量覆盖率、各阶段流失及 R7，不用选择性同意样本宣布市场留存。

**v0.2 补充。** M15 再核对用 interactionId，不抬高新分析完成量。M16 的研究任务记录独立存储，不把 benchmark 参与者纳入自然 R7；任务／报酬／提醒资格未知时单列。业务维护任务、客户标签与付款凭据不进入匿名事件。主观有帮助、完整任务正确性、出站和成交分别呈现。

## M02. 单位成本与用量保护

**目标与基线。** 让免费体验、套餐和商业客户都能在既有预算内运行，并得到可解释的单位成本。已有全局预算、限流、缓存、并发合并及熔断；已有调用统计不等于完整的按流程成本账本。

**当前交付。** A04 已在本地接入请求／流程归属、版本价格快照、缓存受益及 unknown 汇总，见 [成本说明](./request-cost-accounting.md)；尚未部署，真实价格为空。A05 已交付 [客户周期成本与影子权益 fixture](./customer-cost-reports.md)；A11 已提供预算耗尽的东京次日零点恢复提示，保留输入和本机列表。真实单价、账单、工时与权益仍未建立。

**阶段拆分。** a（A 阶段）交付成本关联、报告、已有预算的友好提示，以及不扣真实权益的影子计数／fixture；b（C 阶段）在事务持久层及恢复验收通过后执行真实套餐权益。下面第 4 项及真实余额属于 b，不能用有界 JSONL 实现真实扣减。

**首版流程。**

1. 运营者维护版本化价格表：供应商、模型／SKU、单位、币种、生效区间、免费层与价格来源。没有价格或 usage 的请求标记 unknown，不填 0。
2. 每次真实上游尝试记录 `requestId` 与触发 runId／interactionId。失败、fallback、审计同样进入运营总成本；缓存命中记录免新增调用。
3. a 阶段沿用真实的今日全局可用状态，不显示尚未启用的个人套餐余额；b 阶段用户点击核对时才显示可能用掉的套餐权益。全局或真实个人额度不足均保留输入和已存清单，分别解释限制及恢复时间。日文示例：“今日の確認回数を使い切りました。保存したリストは引き続き見られます。”
4. b 阶段用 `operationId` 原子预留套餐额度；产生终结核对结果后提交；认证／预算／上游完全失败则释放。重试同一操作不重复扣减。a 阶段只演算该状态机，不拒绝用户的“套餐不足”或显示虚构已购余额。
5. 报告实际调用次数、标价估算、免费层后估算（账户全量已知时）、供应商已出账金额及差异。不同币种不直接相加，换算必须标注所用汇率和日期。

**计数契约。**

- 全局供应商预算按“准备发出实际调用”扣减，失败也不回退；套餐额度按已交付核对结果提交，两种计数不能混用。
- `analysis_credit` 对应一次用户确认具体门店后的终结结果，包括有依据的“信息不足”；在开始前解释此范围，不承诺查到可订座席。
- 初期候选评分预览继续受服务端独立速率／全局详情预算约束，不按按钮次数承诺无限预览。未来免费／付费额度值由成本报告决定，不在代码或本文默认无上限。
- 相同 operation 的缓存／重试只提交一次权益；新操作即使利用缓存也按套餐约定计一次交付。暂停恢复没有新成功结果则不扣第二次。
- 并发合并仅记录一次实际上游成本归属给触发者，同时记录受益次数；另行报告共享摊销口径，不能把同一次调用重复计费。
- 没有账号时可用限时服务端会话／已签发 pilot 参与资格辅助计数，不能宣称可防清存储或多设备套利；全局保护仍为最终上限。

**状态、数据与接口。** 权益 `available/reserved/committed/released/expired`；提议 `GET /api/usage` 与服务端 ledger 内部方法；运行／账单状态不向普通用户暴露 Key 或供应商细节。周期先统一东京自然日，商业套餐再采用明确结算周期。价格失效不自动涨预算。

**异常。** 重启回收可证明未交付的过期预留，已提交不回收；预算、账本或时间状态损坏时停止新收费核对，仍可读本机资料。实际供应商成本发生但产品失败时释放套餐额度，成本损失仍计入报告。

**验收。** a：双模型实际调用都计成本；缓存不重复计上游；日报不能漏掉失败／audit 成本；价格未知不会使总成本显示虚假低值；影子计数不改变用户实际权益。b：并发最后一个额度只成功预留一次；失败释放但供应商预算不回退；重启后计数一致；唯一约束、事务、预留超时和故障恢复测试通过后才允许售卖／执行真实权益。

**依赖／指标。** M01 的关联 schema，未来 M11 复用账本。报告全部运营成本、每完成流程平均可归属成本、失败损失、缓存收益、客户贡献；历史免费层不能证明放量盈利。

**维护成本设计。** A05 增加 WorkLog 与周期成本 fixture；B 阶段录真实工时。category 为首次核验／重复核验／纠错／沟通／返工／客服，单次录入实际分钟和 operatorId，零工时必须明确记录，未知不是零。工时单价及固定成本分摊方法版本化；同一 task 分摊和 API 尝试不重复计入多个客户。

客户周期报告分别展示：报价、已收净额、退款、API 标价估算／已出账、人工成本、客服及渠道成本、获客前后贡献。币种分别计算，缺价格／工时／账单时报告完整性和可知小计，不给伪完整毛利。贡献不是全公司利润；售卖容量还要扣除核心用户及失败重试所需预算，不以存储条目数承诺全部可分析。

## M03. 本机任务整理与批次恢复

**目标与基线。** 先减少中断和重复处理，不把资料夹扩建当主要卖点。已有计划、历史、30 项待核对队列和多行输入。a 是首批任务恢复，b 是有需求后的集合／标签。

**当前交付。** A06/A07/A11 已在本地实现以下 a 流程，未部署；存储迁移、恢复和导出边界见 [本机存储说明](./local-task-storage.md)。浏览器已验证可见导出内容与手动保存退路；内置浏览器未返回文件下载回执，不能声称原生文件落盘已核验。b 仍按需求门槛后置。

**a：流程与界面。**

1. 本机任务页分为“行きたい／確認待ち／最近の確認”，分别承载计划、未完成输入和历史；不混合成社交信息流。保留既有排序。
2. 计划可写最多 500 字自写备注，并搜自写店名／备注；可记想去、本人已预约、已去、跳过。系统建议独立显示，不改用户进度。沿用当前容量；不为新标签默认扩大数据上限。
3. 新 batch ID 关联已有线索，页面显示“2 / 5 件を確認”，单项 pending／reviewing／completed／failed／skipped；只对当前项显式分析。失败可修改本项重试，成功项不重跑。
4. 暂停保存结构化线索、批次进度及当前编辑草稿，不保存截图。重载后从未完成项恢复；需要图片重新识别时明确要求重选，不能承诺重载后还能恢复原图。
5. 条目正文打开本机资料；“最新情報を確認”是明确触发详情复核的独立动作。原版重开即刷新的路径已在 A11 分开为上述两个动作。自动恢复页面不请求上游，显式核对仍可能命中缓存。
6. 单项删除可撤销；导出／清空分开选择计划、队列和历史，不清 pilot 凭证。导出只有自写资料、Place ID 和经允许的核对元数据。

**b：后置范围。** 真实任务显示需要时，增加最多 20 个集合、每项最多 5 标签、最多 200 计划的有界方案；集合标题最多 80 字。额度不是既有容量事实，实施前核实。集合／标签不成为批次恢复的先行依赖。

**数据与接口。** 全本机 storage service，SavedPlanV2／BatchState 采用 schemaVersion、UUID、revision；保存 userProgress，lastReviewedAt／lastReviewOutcome 与 userProgress 分开。只有 M15 返回合格真实核对结果才更新核对元数据；失败、demo、打开本机资料或读取旧缓存记录不改成新核对。API 缓存命中后的实际核对可更新 reviewedAt，但来源 fetchedAt 不因此改为现在。

**迁移与异常。** 对旧对象明确列白名单，不保留任意未知字段／第三方 snapshot。备份经过同样白名单的旧用户字段和 ID 映射；不复制旧第三方详情。原 reserved 转为“本人记录已预约”，needs_reservation 不强化事实。迁移失败保留唯一原始数据但不渲染／导出禁止字段，允许安全导出及重试；成功后删除不许可旧字段，兼容原计划引用。localStorage 失败保留当前内存草稿；离线可整理，真实核对需联网。批次超过 30 项说明未导入部分，不静默截断。

**验收。** 迁移保留用户计划且未知旧字段不泄漏；返回修改／重载不重做成功项；原图未保存的恢复提示准确；开启任务页／搜索／导出不上游调用；成功复核后计划元数据更新、失败不更新；同店不同日期计划不覆盖；待核对项不算分析完成；清空按数据域执行。

**依赖／指标。** a：已有 storage／queue、M01、冻结的 M15-a 元数据契约；该契约不要求先完成 A11 实现，A06 可先迁移并供 A11 使用。b：真实整理需求。观察中断恢复成功率、重复识别次数及主动复核，不把收藏数当价值证明。

## M04. 需求、报价与商业证据

**当前交付。** A08 已提供 [访谈／同版报价与证据分层](./business-interview-and-offers.md)、离线汇总和可选消费者研究卡。注册表默认空、卡片关闭；`GET /api/offers` 只读配置，受保护 `POST /api/price-signals` 对未启用方案拒绝。匿名意向不作为实付、G1 或 GB；尚无真实报价、访谈或客户任务。

**目标。** 优先验证具体餐厅维护任务的付费价值，消费者套餐保留有限研究。流程设计把意向、实际付款、客户验收、续购和退款分开，避免先做自助支付才能验证付费的循环。

**A：研究与报价。**

1. 访谈 5–8 位实际维护者，记录最近任务、条目数量、更新原因／频率、替代工具、首次／重复核验工时、出错后果及报告是否真的被使用。不读取私密账号、DM 或未授权客户资料。

4. 消费者反馈放在任务完成后的自愿区域，一个有界方案／版本即可；原 ¥300–500 仅是早期研究假设，不是选定售价。业务付款不算消费者付费。
5. 匿名价格选择 interested／not_needed／too_expensive／unsure 与候补信息分离；联系资料仅主动提交及同意后进入受保护存储，没有邮件供应商不声称完成邮箱验证。

**B：实际商务记录。** 运营者在已批准服务和收款方式下记录 quote_accepted → contracted → paid → delivered → accepted → renewed；这些是独立事实及时间，不要求事件按单一顺序到达。每周期关联 offerVersion／deliveryRevision、脱敏付款证据、实收／退款金额币种及验收证据。合同承诺、转账截图和客户口述不自动等于到账；无法对账标 payment_unverified。续购需新周期真实付款，不以自动续费开关、免费延长或“愿意续用”代替。

人工商务试点不要求 M08/M11；收款渠道、收费说明、客服及退款安排在真实执行前另行确定并遵循项目批准边界。B07 只是私有记录，不自动发票、扣款、发权益或对外发送消息。

**状态、数据与接口。** A 沿用提议 GET /api/offers、POST /api/price-signals；offer=draft/active/paused/retired，waitlist=unconfirmed/confirmed/withdrawn。B 使用 ServiceCommercialRecord／DeliveryCycle 的本地保护工具，无客户公网写入 API。未获批准的真实报价／付款不得拿 mock 状态填业务报告。候补资料默认 90 天到期；商务事实与证据的保留／删除独立确认，普通事件无邮箱、合同或付款明细。

**异常。** 价格或服务范围改变生成新 offerVersion，旧接受不能迁为新版本承诺；不匹配金额／币种进入待核对；部分退款、撤销、欠交付和争议保留历史。服务容量不足暂停新接受，不承诺额外付费调用。联系撤回与研究同意撤回分别处理。

**验收。** 未提供方案无“立即购买”；权益／价格／服务范围完整；报价信号、合同、到账、验收和再次到账分开统计；两个客户的同意不能自动标 GB 通过；重复付款证据 ID 幂等，跨币种不直接相加；付款无交付可追踪，退款修正实收；候补撤回可执行。

**依赖／指标。** M01、M02 成本范围、M15/M07 交付引用；真实商务动作按已有授权边界执行。G1 用明确价格接受和真实任务；GB 需至少 2 位各完成首周期与付费续购周期的交付／验收，逐客户逐周期贡献为正。续购仅到账不通过，未量化成本不通过；已知用量／价格可计算保守成本上界，明确估算而非实际账单。阈值为探索假设，不是市场付费率。

## M05. 核对交付清单与可选发布

**目标与切片。** a 为私有业务交付，b 才是创作者向读者传播的托管清单。维护服务无需先发布公开地图或取得佣金。

**a：私有交付流程。**

1. 运营者从 M15-b 本周期记录创建独立 DeliveryDraft，不序列化工作区或私人计划。逐字段经 FieldPolicy 投影：客户提供／授权内容、自有核对结论及许可来源引用。
2. 逐店展示客户线索、确认的身份范围、各字段结果、实际来源时间／未知、下次复核任务、unresolved 原因及本周期交付范围。身份冲突或无证据不能有“已核对可预约”标签。
3. 草稿预览包含公开／导出字段说明，但原截图、原始 API 详情、用户预约 URL、联系方式、工时单价、内部备注与付款资料不混入交付。
4. 首版客户在受控审阅会话确认，或经授权导出有界 UTF-8 Markdown／JSON 交付文件。文件含 revision、生成时间、事实核对时间含义、允许字段；导出不自动发送，也不新建公开 URL。
5. 客户 accepted／changes_requested；修改产生新 revision，旧验收绑定旧版。每项 resolved／unresolved 均可在约定范围内交付，但 unresolved 不计已解决条目；客户验收不是事实认证。

**a 数据与接口。** DeliveryDraft／DeliveryCycle 引用 recordId 和 reviewRevision，输出白名单；首版通过私有本地工具，不建匿名下载 API。可复制的交付文件无法远端撤回，界面如实说明；后续修订需独立交付，不能宣称旧副本消失。真实文件存储与外发按照客户授权和保留范围执行。

**b：可选托管阅读流程。**

1. 有真实读者需求后，从 a 创建独立 PublishedList，作者自写标题／介绍和有公开许可条目；字段公开许可与私有交付许可分别检查。首轮最多 10 活跃清单、每张 20 店。
2. 客户确认发布预览后，生成至少 128 位随机 readToken，默认 30 天到期、noindex；持链接者均可读，这不是邀请制私人权限。未知字段和内部 reviewRecord ID 不输出。
3. GET /api/lists/:readToken 返回只读 PublicEntry；普通读页不上游调用。阅读时间与“作者提供／截至何时核对”清楚区分，历史支持入口不当作当前已核验预约。
4. 读者选店后主动点击“この店舗の最新情報を確認”。readToken 只读，不授予 pilot 分析／事件写权；没有资格时保留选中条目并引导 /pilot 与访问码。分店确认和预算不跳过。
5. 可撤回／轮换 token／到期／删除，旧 token 不重定向新 token；接口和页面不返回撤回内容。读者已保存的获准自写副本不能远端删除，后续自行核对。

**状态与安全。** a：draft/review_requested/accepted/changes_requested/superseded；b：draft/published/unpublished/expired/deleted。B 阶段只有内部管理身份可写，pilot code／readToken 不授权管理。HTML／接口禁止共享缓存私人内容，禁止 XSS／危险链接；受保护预览不生成泄漏标题的社交卡。未授权阅读最多记录服务端粗总量，不豁免受保护埋点 API。

**异常。** 来源许可或有效期不满足时字段剔除并保留 unresolved，不复制缓存 API 内容补齐。身份冲突使受影响入口失效；工作区停用停止新发布。来源未刷新仍 unknown，不因客户验收升级。预算耗尽暂停核对，已有获准清单可读。

**验收。** a：只输出许可字段；工作区／私人计划不泄漏；修改后需新验收；导出无网络调用且不自动发送；unresolved 与已解决分别计数。b：阅读不上游；撤回后无内容；readToken 不绕 pilot 或管理身份；转发语义真实；任何作者推荐不跳过分店确认。

**依赖／指标。** a：M15-b、M02 的范围／容量、字段登记与保护；b：a＋真实读者需求、M01/M02。a 看交付验收和返工；b 才看读取／核对／出站，不能因低流量否定真实维护工时价值。

## M06. 行动测量与合作归因

**目标与基线。** 建立“出站、成交、可结算、收款”的可核对链条。已有 provider capability 与安全主行动；没有合作协议时普通外链保留，佣金不可假定存在。

**a：无合作也可交付。** 增加行动类型分类：直接预约流程、平台管理预约／代订、电话、地图、排队、普通店铺页、查找入口。来源可信度与费用／取消限制继续在跳转前展示。只增强已有合法外链，不任意改写平台参数。

**b：一个获批准合作方。**

1. 运营者配置合作资格、覆盖门店、合法追踪参数、净佣金算法、归因期限、取消／退款扣回、回传方式和停止日期。
2. 服务端为已核验目标签发不含个人身份的短期关联引用。用户主动点击，才生成 outbound 记录并跳转；第三方域名和路径仍从可信选项中选择。
3. 明确显示“提携リンク：予約成立時に紹介料を受け取る場合があります。”不替换成高佣金但不对应门店的链接。
4. 合作方回传只有验证签名、时间窗、provider conversionId 和允许字段后才能进入账本；没有 webhook 时从允许的脱敏 CSV／管理报告导入，不伪造自动接口。
5. 跟踪退款／取消／更正及结算单。用户自报预约结果只留在 feedback，不改合作账本。

**状态与安全。** `clicked → provider_confirmed → eligible → settled`；可进入 `cancelled/reversed/disputed/unmatched`；没有回传保持 `unconfirmed`，不因超时变成成功。非顺序回传按供应商最新有效事件与状态转换规则处理，不把 settled 后退款丢弃。redirect 仅接受签名引用和注册域名，禁止任意 URL／开放重定向；跳转目标不能含账号或邮箱。

**数据与接口。** 提议 `POST /api/outbound-intents`、`GET /go/:signedRef`、`POST /api/partner-events/:provider`；JSONL 分析日志之外保留可审计 ledger。账本期限按协议与审阅确定；不得仅依现有 30 天裁剪。真实隐私选择与跨站归因安排按合作方要求审阅；不默认加载第三方追踪脚本。

**异常。** 协议到期、目标失效或配置关闭时退回经过核验的普通直链，并说明不计合作归因；不能落到错误店铺或要求用户重付。同 conversionId 重复回传幂等；乱序更新保留历史；无法匹配进入待核对，不加入 revenue。

**验收。** 预约出站不包含地图／排队；普通平台详情不升级为可预约；跳转无开放 redirect；非法签名／回放无账本写入；重复和乱序回传正确；eligible 与 settled 金额分别展示；取消／退款支持扣回；无协议时合作路径关闭。

**依赖／指标。** a：M01 和已有可信行动，不要求托管清单；b：M02、合作和数据／成本授权、账本持久层。报告有效出站、合作覆盖、确认成交、可结算净额、实际收款和每分析净贡献，不把合作方给其他平台的费率当本项目收入。

## M07. 维护工作台与交付报告

**目标。** 为反复维护日本餐厅信息的客户减少人工工作，首版由运营协助。创作者只是可能客户之一；既有审计工作台不是业务后台。

**a：内部工作台。**

1. 本地工具建立 ManagedWorkspace：内部 operatorId 负责，首轮最多 3 客户、各 ≤20 条目；联系资料独立保存。客户提交的任务范围关联 offerVersion／cycleId，未通过字段／服务范围检查不接受真实资料。
2. 默认导航“確認待ち / 作業中 / 要対応 / 納品”。列表列出自写门店线索、受影响字段、待办原因、上次核对时间含义、负责人；不默认展示大地图、流量排行或技术供应商状态。
3. 运营者逐项显式启动 M15-b；记录核对、补充来源、身份冲突、客户需补线索和复核到期。到期视图只排序待办，不自动访问上游。
4. 从 M05-a 创建交付预览，客户审阅／修改／验收；报价意向、付款、验收和续购由 M04 独立记录。实际付费和向客户发出文件继续需要相应授权。
5. 每周期生成工作报告：分配／解决／unresolved、返工、首次／重复核验／沟通分钟、客户基线工时、真实成本及未知项。无可靠基线只显示实际分钟，不宣称节省百分比。
6. 需要向读者传播时才接 M05-b／campaignId；有 M06-a 才显示出站诊断，有 M06-b 才显示合作确认／结算。阅读少不影响已验收的维护交付，点击不当收益。

**b：有证据的自助客户流程。** GB 与 M08-b 通过后，客户 owner 可管理自身范围、邀请 editor／analyst，提交变更、审阅交付和读报告。editor 只能维护获授权草稿；客户提交不直接改变事实可信度。采用工作区身份认领迁移：保留 workspaceId／recordId／deliveryId／campaign／账本引用，记录旧责任人与新 owner。不是必须先同步消费者私人资料；C02 为独立可选功能。

**状态、数据与接口。** workspace=invited/active/suspended/closed；工作状态与 M15 一致。a：本地保护工具／模块内部方法；b：提议 GET /api/workspaces/:id/tasks、/deliveries、/reports 及授权写入端点，使用 revision 校验。清单、字段证据和付款凭据分别 scope；analyst 不读联系／付款个人资料。报告按周期／报价／交付 revision 呈现，不只按页面访问日期。

**报告边界。** 客户自己的交付工时／成本报告不依赖读者数。只有读者细分报告要求 ≥5 个同意研究的去重设备，未知或不足隐藏；非同意读者只进运营粗总量，不提供任意细分。匿名设备不是人数，测量覆盖与 unknown 显示，不以事件数达门槛。无回传成交未知，无工作日志工时未知。

**异常。** workspace 暂停禁止新写／核对／发布；读取交付按保留与授权规则处理。修改来源／删除条目标记相关已交付版本 superseded，不能静默改验收记录。跨工作区 ID 必须被拒，失权即时生效；重启后已完成任务和工时不丢失，失败任务保留。

**验收。** 一个受控维护周期可完成范围确认、逐店处理、unresolved、客户修订、验收及报告；不依赖公开阅读或合作佣金；重复记录不重复计工时／付款；报告有原始分母和未知；身份认领保持引用且权限隔离；业务工具与审计权限分离；客户文件外发不是默认按钮动作。

**依赖／指标。** a：M15-b/M05-a/M02/M04，M01 只用于产品测量；b：GB、M08-b。报告实际验收、重复维护工时、客户续购及获客前后贡献，账户数／发布数不是主 KPI。

## M08. 账号、云同步与权限

**目标与进入条件。** 解决跨设备、自助清单和 workspace 权限；不为单次核对引入账号门槛。只有这些需求明确后实施。

**a：最小 Account/Session 核心。** 按对应分支证据启用：业务由 GB 支撑，消费者由清单中的独立复用／报价付费证据支撑；两者不互相锁定。a 包含账号、会话、本人资源授权、撤销、导出／删除及恢复，登录不自动上传本机计划，不必须有 workspace 或云同步。M11 依赖 a 和自身分支证据，不要求业务 GB 或完整消费者同步。

**b：业务工作区权限。** GB 后增加 workspace 归属及 owner/editor/analyst。验证客户归属后认领 ManagedWorkspace，保留 record/task/delivery/campaign 引用。M07-b 依赖此权限，不以仅有登录或客户端隐藏按钮当授权。消费者账号不自动获得工作区角色。

**c：独立可选的消费者同步流程。**

1. 用户在资料夹选择“この端末のリストを同期”；提前说明数据去向、处理者、保留／删除与可能费用。关闭同步仍可用本机功能。
2. 采用一套经过评估的最小登录方式；可在本地开发 mock。邮件／Passkey／第三方登录的最终选型、供应商和价格尚未确定，不能默认请求新外部权限。
3. 首次登录展示本机集合／计划上传预览；用户选择上传范围，不上传截图和第三方快照，联系人不混入事件日志。
4. 新设备拉取云端资料；离线编辑存本机队列，联网按 revision 同步。冲突给出保留本机、云端或副本，不按设备时钟静默覆盖。
5. 用户可导出、关闭同步、撤销其他会话、删除云资料或账号。退出登录清除本机云 session 和云缓存，原本机独立资料是否保留由用户明确选择。

**状态、数据与接口。** account `active/deletion_pending/deleted`；同步 `local_only/upload_pending/synced/conflict/offline/error`。提议 `/api/session`、`/api/collections`、`/api/account/export`、`/api/account/delete`。会话 HttpOnly/Secure/SameSite，所有写操作检查资源所有权、CSRF／Origin 和 body schema；workspace membership 是服务器事实。

**保留／删除。** 活跃云资料保留到用户删除；账户删除后立即禁止新读写／登录，私有内容从活跃存储删除，关联公开清单撤回，邀请失效。备份副本按经过确认的恢复保留周期到期，不能恢复为活跃账号；订单／法律必需记录依独立审阅保留并最小化，界面事先解释。联系删除不能靠裁剪 analytics 代替。

**异常。** 认证失败保留原本机草稿；冲突不破坏唯一副本；删除后离线设备不能重建已删除数据。容量满不静默增加存储资源。迁移／事务／恢复能力不足时不启用自助账户。

**验收。** 不登录仍能核对；登录不自动上传；他人资源 ID 访问被拒；撤销会话和账号删除即时生效；跨设备冲突可恢复；导出无凭证／第三方详情；备份恢复不会复活删除账号。

**依赖／指标。** a：所属分支证据、事务与恢复、账号／数据范围；b：a＋GB；c：a＋M03-a 和独立跨设备需求。工作区自助不强依赖 c。观察客户实际编辑和交付成本、消费者主动同步／跨设备使用；账号数不是收入指标。

## M09. 朋友共同选店

**目标与进入条件。** 为真实聚餐组织者减少聊天来回和选择成本。M05 的持链接阅读不承担私密协作权限。

**流程。** 组织者从私人计划选择公开给小组的门店条目 → 明确预览 → 邀请指定成员 → 成员登录接受 → 各自投想去／可接受／不方便 → 组织者确定一家和计划 → 由明确的人到外部平台核对／预约。首版最多 10 成员、20 候选；不收集定位、自动读取通讯录或分析聊天。

**状态、数据与接口。** group `draft/voting/selected/closed`；invite `pending/accepted/revoked/expired`；vote 每成员每 entry 一条可修改。提议 `/api/groups/:id`、`/invites`、`/votes`；邀请 token 有有效期且不能独立获得永久写权。用餐日期／人数只对成员显示，不流入商业事件。

**边界与异常。** 组长设置负责预约者；“已预约”注明成员自行记录，不代表系统确认。离组／撤销立即失权；链接泄漏只到登录／接受页。删候选时保留必要操作记录并说明投票失效；并发选择按 revision 拒绝过期写入。

**验收。** 非成员不能读私人日期／投票；成员不能替他人投票；撤销邀请失效；选中餐厅不自动预约／付费；返回修改保留已有投票并清楚标记适用版本；只有匿名总量进入商业报告。

**依赖／指标。** M05-b/M08-a/M08-c/M03-a，独立组织聚餐需求；观察建组到选店完成、组织者复用和实际协作次数。首版不做公开排行榜、聊天或拆账。

## M10. 日历导出与可选提醒

**目标与进入条件。** 在用户已保存计划的基础上，帮助记得再次核对；不暗示持续监控了空位／营业变化。

**a：低成本首版。** 在计划详情提供“カレンダーに追加”，用户主动下载 .ics；用户选择提醒时间，使用 Asia/Tokyo，说明日历 App 最终决定是否提醒。只写用户自填的名称／日期和 TabiTabi 核对入口；私密入口不放可被第三方直接读到的 token。离线可导出，创建日历事件不调用供应商。

**b：可选通知。** 需求成立后才申请浏览器／App 通知权限；首次访问不弹权限。订阅由用户确认，提醒只说“出発前に最新情報を確認してください”，点击回到需主动核对的计划。通知／邮件供应商价格和数据处理另行批准；不默认后台轮询全部保存店。

**状态、数据与接口。** reminder `off/scheduled/delivered/cancelled/error`；a 全本机，b 需要 M08 和受保护订阅接口。避免混用过期计划／设备本地时区；更新日期取消旧任务。通知文本不含私人备注、用餐人数或具体预约状态。

**异常。** 没日期时先编辑，权限拒绝提供日历选项；应用不能证明 .ics 已导入，只报告已导出。删计划撤销订阅；已送达重复任务不再发；旧核对结论不能变成“今天仍营业”。

**验收。** ICS 转义与日期正确；导出不产生上游费用；不宣称系统保证通知；取消后不再发；提醒产生的复用独立标记，不能混入自然 R7。

**依赖／指标。** a：M03-a；b：M08-a 和通知审批。观察导出、提醒后主动核对、拒绝率；通知点击不称预约成交。

## M11. 自助支付与真实权益

**目标与进入条件。** 把已获验证的一个价值主张变成可靠收费。先实现一种套餐，不同时上线订阅、次数包、团队席位和所有游客服务。

**流程。**

1. 展示价格币种、含税口径、周期、明确用量／权益、续费方式、取消／退款及第三方餐厅费用不包含在内。
2. 用户主动进入支付方托管 checkout；支付方保存卡片，TabiTabi 不接收卡号或第三方餐厅账号。
3. 服务端创建 pending order，使用唯一幂等键；成功跳回页只显示处理中，已验证支付事件到达后才授予权益。
4. 权益由 M02 服务端账本控制；套餐额度不足和全局预算停止分开解释。全局上限仍生效，不能售卖无法兑现的容量。
5. 用户可查看当前周期／余额／订单、取消续费、申请适用退款。支付失败、争议和退款通过可核对规则改变权益。

**状态与数据。** order `pending/paid/failed/cancelled/partially_refunded/refunded/disputed`；subscription `trialing/active/past_due/cancel_at_period_end/ended`（只在最终选择订阅时采用）。提议 `/api/checkout`、`/api/billing/events`、`/api/billing/portal`；签名、eventId、orderId、金额／币种／planVersion 核验。退款更正保留历史，不能重放成功回调恢复已退款权益。

**异常与承诺。** 重复回调幂等；回调晚到不要求重付；金额不符不激活；付款后服务不可用有明确恢复／退款流程。购买前依据当前预算和已售容量做售卖限制；全局止损时暂停新售卖，私人资料仍可读。欠费不能扣留用户自写资料导出。

**验收。** 沙箱购买／失败／取消／重复与乱序回调／退款／争议／重启全部测试；前端伪造成功无权益；实际付款前完成收费信息与适用法律专业审阅；真实支付测试按独立费用授权执行，mock 或沙箱通过不称正式收费可用。

**依赖／指标。** M02/M04/M08-a、对应报价的实付／续购与贡献证据、支付供应商选型和账本事务、收费授权、客服／退款规则。早期运营协助的获批人工收款不依赖本模块。报告实收、退款、净收入、履约成本和续用；候补和 pending order 不计收入。

## M14. 访日游客一次性服务

**目标与进入条件。** 独立验证是否有人愿意为一趟旅行的餐厅整理和语言／人工协助付费；不改变日语核心产品默认方向。

**可出售范围。** 自动整理可为短期权益；人工核对有逐项交付、响应时间、可服务语言、营业时段、失败／取消／退款规则。代订、电话或付款不包含在整理服务；若后来提供，需另行定义客户授权、账户／付款处理、责任和合作资格。

**验收。** 明确城市／数量／期限／语言／费用／非代订范围；未提供服务不能收费；失败和退款有流程；行程不可被未授权者读；游客漏斗与国内用户分别报告；没有空席证据不宣称可订。

**依赖／指标。** 运营协助研究：独立需求、M03-a/M15-b、人员及数据／费用授权，可用获批人工商务流程；自助 API／收费才需 M08-a/M11。报告单行程净贡献、人工分钟数、交付及时率、退款及满意度，不与国内自然复用或月会员留存混算。

## M15. 核对摘要与复核任务

**当前交付。** A11 已实现 a 的逐来源时间、摘要、保留草稿纠错及复核元数据；用户选店时间仅来自本次客户端明确操作，服务器不猜测，主动复核不伪造一次新选店。A12 已提供 [字段许可／任务／私有交付 fixture](./review-workflow-fixtures.md)，b 的真实工作区与交付仍待 G1。

**目标与基线。** 将已有证据约束转为用户可理解、运营可维护的任务。复用 `decisionEvidence/evidenceFacts/risks/reservationOptions.capability`，不建立实时空席系统或永久第三方餐厅库。当前没有结构化复核记录、字段纠错工单或独立 `sourceCheckedAt`；其中部分官网事实时间沿用 Places 时间，需先改为真实来源时间或未知。

### a：消费者核对摘要、纠错与再次核对

**用户路径。** 输入并主动分析 → 修正线索 → 确认具体分店 → 结果首屏 → 可信行动／返回纠错／保存；再次核对从本机计划显式启动。

结果首屏低保真结构（示例文案，不是真实餐厅数据）：

```text
○○ 上野店                 [分店を選び直す]
上野・あなたが確認した店舗

次の手順：予約先で条件を確認する
[予約ページで確認する]
このリンクを開いても予約は確定しません。
支払い・取消など判明している重要条件はボタンの直前に表示。

今回の確認 10/02 14:10  [確認した情報と時刻]
一部の情報は取得時刻不明／要再確認ならここで短く表示。

[保存]  [この情報に問題がある]
[判断の理由・情報源を開く]
```

主按钮由实际能力生成，可能是电话、地图、官网或预约入口，不固定为“预约”。已关闭、身份冲突和关键来源冲突靠近主动作，必要时禁用受影响预约动作；详细来源和模型信息不挤占第一屏。未知状态提供电话／来源核对等安全退路，不能表现为已确认营业。

**时间契约。**

| 字段 | 含义／更新条件 |
| --- | --- |
| `resultGeneratedAt` | 本次结果计算时间，不是每个来源重新抓取时间 |
| `sources[].retrievedAt`／`sourceRetrievedAt` | 实际该来源获取时间；缓存沿用原时间，官网必须自己的时间，缺失为 null |
| `identityConfirmedAt` | 用户本次确认分店的时间，不表示店方认证 |
| `lastReviewedAt/lastReviewOutcome` | 用户主动复核得到终结结果后的自有元数据，失败／demo 不更新；unknown 明确记录 outcome |
| `dueAt` | 业务约定下次应处理时间，仅排任务，不代表来源有效至该日或已持续监控 |

现有 60 秒详情与 10 分钟官网缓存继续受控，不默认增加强制刷新参数或破坏合并请求。再次核对可命中缓存，界面展示实际获取时间；任何来源没有可靠时间就标未知，不能取最晚时间替代全部来源。未来强制重取若确有必要，应单独定义操作、去重和费用范围。

**纠错流程。** “分店を選び直す”回候选，保留用户线索／已提取结构，只清失效的所选门店及下游结果。修改名称／地区时更新唯一草稿来源，相关候选作废；改计划日期／人数不重跑截图，只在显式核对时处理。新增问题反馈仅收 wrong_branch／wrong_link／outdated_info／unclear_condition／other 枚举，不新增自由文本或图片。它用于匿名诊断，不承诺逐店客服回复，不直接修改全站事实或封禁餐厅；错误分店先引导本机重新确认。既有最多 500 字的用户主动反馈保持原 schema／隐私范围，不复制进入 CommercialEvent v2。客户工作区有明确记录关联的纠错由 b 独立处理。

**数据与接口。** 增强已有 `POST /api/restaurants/details` 的返回元数据及时间来源，新增字段 schema/version 明确；主动复核由 interactionId 关联，不写新首次分析完成。问题分类只以 CommercialEvent 的 issue_category／runId 或 interactionId 复用受保护 `POST /api/events` 校验；无自由文本、来源 URL 或餐厅详情，不为匿名反馈绕过 pilot。完整 `VerificationView` 仅内存；SavedPlanV2 只保存许可的最小元数据与自写线索，不保存 `restaurant/evidenceFacts/risks/reservationOptions` 全量快照。

**状态与异常。** identity=unconfirmed/confirmed/conflicted；actionEvidence=unchecked/supported/unknown/conflicted；请求=idle/checking/completed/failed。supported 只表示本次证据支持该行动类型，不是空席或预约成立。拒绝访问码、超预算、上游失败、断网均保留当前输入和计划；旧元数据不覆盖成成功。疑似时钟异常将来源时间标未知。关键冲突在 API 决策和 UI 同时受控，不能只用 CSS 隐藏。

**验收。** fixture 覆盖同名分店、闭店但有旧预约链接、搜索页误升级、费用／取消限制、未知时间、Google 新／官网旧、缓存命中、低置信度、返回修改、失效访问码、超预算及离线。官网时间不借用 Places 时间；旧保存项复核成功更新元数据，失败不改；修改一个字段不重传原图；折叠证据可键盘操作、展开后焦点可预测；日语 320–430px 首屏主动作与重要限制可读。UI 实施用 in-app Browser，未开展真机验证不称 iOS Safari 已证实。

### b：内部逐字段维护与复核任务

**开始条件。** A12 可先做 fixture；真实工作区依 G1、字段许可和内部保护。首轮最多 3 工作区、每区 20 条目，不自动按次数消耗 API；先确认可交付字段、人工时段、更新频率和任务容量。

**运营流程。**

1. 将客户自写线索导入 ReviewRecord，关联 workspaceId／cycleId／Place ID；没有确定身份时保持 unconfirmed，不以模糊同名门店补齐。输入不能含未授权私人截图／DM。
2. FieldPolicy 登记每个字段来源、保存目的、保留期限、导出／公开权限、审阅依据和版本；未评估默认不复制。地址、电话、营业、评分、预算及预约详情等第三方数据默认只在本次核对内存使用，是否允许保存／交付需逐项有依据。`place_id`、自写内容与可保留核对元数据也按各自来源区分。
3. 运营者选择一项并明确核对，先预估当次操作及剩余预算，不启动整表并行刷新。源不可用、真实时间未知、身份或入口冲突生成明确待办；失败和未知记录工时，不填空白为正常。
4. 可记录自己的结论、核对方法和获许可来源引用，必要时人工复核门店名称与地址及具体入口。现有官方来源验证范围有限，新增人工记录标为 operator_checked 并列方法／时间；不自动注入全站“官方已核验”名单，不以客户验收替代来源核验。
5. 字段状态为 pending/supported/unresolved/conflict/not_applicable，分别记录身份、营业状态、入口类型与已核对条件；不压成一个绿色总分。当前只确认线上入口时，未核实规则和席位仍 unknown。
6. 在私有记录内创建 ReviewIssue（open/in_review/resolved/rejected），关联 recordId、受影响 revision／字段及 actorId，确认后生成 linked ReviewTask；匿名问题类别只作汇总，不能自动生成带餐厅身份的工单。处理结果需要自身来源证据，不能直接采用投诉内容。
7. 填实际人工分钟及处理结论，完成本项／需客户补线索／待再次核对。约定 dueAt 到期只显示待办，不能后台轮询；修改关键来源使相关草稿失效，客户重新审阅后才交付新版本。
8. M05-a 按白名单生成本周期交付，M07 汇总工时／返工；每条 unresolved 提供原因和下一动作。不能用旧 API 详情或无许可材料填缺口。

**任务状态。** pending → in_progress → completed 或 blocked；blocked 记录原因（缺线索／冲突／预算／源失败），补齐后人工回 pending；completed 后有新证据／到期创建新的 linked task，不重写已交付历史。可 cancelled；工作区 suspended 时停止新任务。

**存储与接口。** 首版私有本地维护工具的 `createReviewTask/startReview/recordFieldReview/completeTask/createDeliveryDraft` 方法，期望 revision 和 workspaceId 必填；不是匿名公网 API。每个动作记录 operatorId、时间、受影响字段及版本，不记录截图／来源全文。复核元数据与自有工时默认试点结束后 90 天到期，实际客户合同／许可有更短期限则用更短；商务必要记录另有保留规则。来源内容的更短许可期限优先，不因记录保留 90 天而延长详情缓存。

**异常与并发。** 版本不符拒绝覆盖，保留修改供对比；删除来源／许可到期清除不可保留字段，并令相关交付待修订。导出文件的既有副本无法远端清除，交付前如实告知。损坏／无法恢复工作记录则暂停真实写入，旧交付只按允许范围可读；原子替换与恢复验收用 fixture，不用生产数据演练。

**验收。** 逐字段来源／时间／许可可追溯；缺失不可导出；公共问题反馈不能全站改事实；scope 与 revision 防越权／覆盖；到期视图和打开工作台不请求上游；部分失败可单项续做，完成项不重扣；重复工时幂等；重新核对生成新版本且旧验收不迁移；来源失效／身份冲突能使相关行动退出可交付状态。

**依赖／指标。** a：M01/M03-a/M16 协议；b：M02/M04、G1、字段登记／私有写保护，交付由 M05-a/M07-a 接续。看全任务正确性、纠错耗时、复核解决率、总人工分钟与验收／续购，不能以“核对过多少店”替代维护价值。

## M16. 同案例质量与效率评估

**目标与基线。** 验证 TabiTabi 相对用户常用“Maps＋官网／预约平台”及可用直接竞品的增量。复用现有 `eval/cases.json`、候选／决策回归和人工审计定义，新增离线研究记录与比较；不重建模型评审，不把 Qwen／OpenAI 当独立裁判。

**协议流程。**

1. A09 在体验修改前保留可复现 baseline，并确定任务目标、rubric、主要路线、case 配比与统一时间上限（首轮建议 5 分钟）。待 candidate 构建及真实案例准备好，在任务采集前冻结 protocolVersion、baselineRevision、candidateRevision、groundTruthVersion、案例名单、配比、设备／地区可用性及上述规则；不能用占位 revision 开始真实比较。BaselineSnapshot 记录旧版本的可复现 checkout／构建标识、配置 fixture 及保留位置；不能只留下一个 revision 而无法运行。三条必需路线为旧版 baseline、新版 candidate、一个 primaryReference（默认 Maps＋官网／预约平台并冻结具体操作路径）；直接竞品是 secondaryReference，只作诊断，不能选最有利对象替换主要比较。
2. 每案例使用人工确认的 groundTruthVersion，记录实际门店／分店、预期可行动或必须未知、入口类型、核对来源及日期。真值不足先修案例；已失效案例标为 invalid_truth，三条必需路线对称处理，分配总量／排除数仍报告，不能只删 TabiTabi 失败项。
3. 至少 30 个去重案例、10–15 位目标参与者；各有效 case 均有 baseline、candidate 和 primaryReference 记录，至少 90 个分配任务，不把任务次数称案例数。常规和难例事前配比，匹配同一真值有效期；路线由不同参与者／平衡交叉分配，先后顺序平衡，避免同人立即重复同案。同参与者／案例重复不是独立样本，记录依赖与分层。修改前 baseline 可在冻结协议后先采集，或用可复现旧版本补采；没有对应真人任务证据时回归比较仍未知。
4. 计时从展示任务并允许输入开始，包含上传、输入、确认、纠错和行动选择。结束为提交可判断的终结结果／退出／时间上限。外部点击没有确认门店及行动理解，不能标 success。真实预约成立不属于本轮任务要求，另有实际服务证据。
5. 人工评分使用真值与冻结 rubric，记录 reviewer 与原因；不确定评分复核，不用另一模型投票自动升级。工具确定性验证唯一任务 ID、时间、路线覆盖、结果枚举及版本。
6. A10 离线汇总三条必需路线的总分配／有效／未完成／排除、整体与可行动子集的正确完成、错误、未知／弃权／超时、成功耗时分布及门槛。至少 30 个同一有效案例均有三路线记录才判 GQ；不能按路线单独挑成功案例。既有记录缺失不是从分母删除，结论 insufficient_evidence；次级竞品记录不足不影响主要协议，但报告其缺口。

**结果枚举。** correct_action：正确分店及适当行动；justified_unknown：真值预定须未知且用户正确理解；incorrect_unknown：可行动案例被拒答或未正确解决；wrong_branch／unsafe_action／wrong_action；abandoned；timed_out。字段 missing/invalid 与 incomplete_attempt 独立报，不默认视为成功。

**计算契约。**

| 输出 | 分子／分母或统计方法 |
| --- | --- |
| 全任务正确完成率 | (correct_action＋justified_unknown) / 全部有效分配任务；失败、未完成、弃权、超时保留在分母 |
| 可行动案例解决率 | correct_action / 真值为可行动的全部有效分配任务；incorrect_unknown 不成功 |
| 未知／弃权／超时 | 各枚举次数／全部有效分配任务，另列未知是否符合真值 |
| 关键错误 | wrong_branch 与预定义 unsafe_action 的次数、涉及 case 与分母；不以成功率掩盖 |
| 成功任务耗时 | 只对正确完成且时间可信项算中位数／分布，同时列样本数；不能把失败从完成率删掉 |
| 耗时下降比 | (主要替代路线中位数 − candidate 中位数) / 主要替代路线中位数；≥25% 为探索改善路径，缺值或零分母为 null；旧版变化另列 |

GQ 回归保护：candidate 对 baseline 的全任务正确完成率／可行动解决率不下降且无新增关键误导。GQ 替代价值：candidate 对 primaryReference 也满足相同保护，再满足耗时下降 ≥25%，或难例关键错误减少且常规成功任务耗时增加 ≤10%。时间和难例增量均只对 primaryReference 判断，secondaryReference 不参与通过逻辑。三路线、同案例、同真值有效期和冻结分层不足时证据不足。小样本观察不证明总体无风险或统计显著；fixture 通过不是真人 GQ 通过。Benchmark 参与者不进自然 R7。

**数据／接口。** 已提供 `benchmark:validate`、`benchmark:summary` 本地命令读取 BenchmarkProtocol／GroundTruth／Attempt 文件，及 `benchmark:baseline` 保留／验证／重放旧版；默认 fixture/provider-free，不含自动网络调用。当前完成范围和实际 schema 见 [评估工具说明](./benchmark-protocol.md) 与 [实施记录](./implementation-progress.md)，尚无真人 GQ 结果。真实任务输入与来源按授权只在受控研究域使用，参与者编号不用邮箱／账号，不进产品事件日志；默认原始研究记录最多 30 天、不可反推匿名汇总最多 90 天，当前由负责人到期检查，自动删除尚未实现。输入图片不写入应用日志，案例材料按已有人工案例的内容范围单独管理，不把普通用户图片保存为评测集。

**异常。** 参与者中断或 UI 错误记失败／退出不重置计时；比较路线不可用在分配前排除并记录，分配后故障另报，不按无缺口胜出。真值更新产生新版本，不混旧版和新版通过率；必要重新评测须重新确定费用和样本范围。缺失／未知不得补成 0。

**验收。** fixture 覆盖全失败、全拒答、关键误导但很快、缺时、超时、真值失效、对比路线缺失、重复任务、混合版本和零分母；全拒答在可行动案例不能通过 GQ；成功中位数下降但整体完成率下降不能通过；协议未冻结／数据缺失结论为未知；报告含完整分母、旧版完整任务证据及唯一主替代路线；只有旧 revision 无真人 baseline、缺一个必需路线或任一必需任务时间缺失时不得通过。沿用回归测试检查既有决策，不把研究通过替代发布 gate。

**依赖／指标。** A09 可独立做，A10 依协议和完整记录；M15 改动先有冻结基线。新增真实付费识别、竞品购买、客户资料和参与者联络在执行前按各自范围授权；本设计不启动它们。核心 KPI 为正确完成／完整任务耗时，M01 的确认后 API 耗时另列为诊断。

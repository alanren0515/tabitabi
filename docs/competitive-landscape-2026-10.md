# TabiTabi 日本与国际竞品分析及项目前景判断

研究日期：2026-10-02。价格和功能以本次读取的官方网页、帮助中心和开发者商店说明为准；后续可能变化。

后续已将本报告与开发文档综合为 [功能开发清单 v0.2](./next-feature-roadmap.md) 和 [功能模块设计 v0.2](./feature-module-designs.md)。本报告保留当日研究与建议；下一轮实施范围、依赖和进入条件以两份综合规格为准。

本报告用于决定下一轮开发投入和市场验证方向。研究覆盖直接的 SNS／截图转地点工具，以及替代用户最终行动的预约平台。未登录、购买或上传内容实测竞品，也未读取 TabiTabi 最新生产留存、账单和成交数据。官方功能说明可以证明公开产品定位，不能证明识别准确率、实际覆盖、付费人数或盈利。

## 1. 判断与建议

**建议继续做范围有限的验证，并收紧产品定位和开发清单。** 当前证据更支持探索日本餐厅核对工具或垂直运营服务，尚不足以支持全面开发全球旅行平台、通用收藏 App 或消费者订阅体系。

此前“有限免费消费者入口＋优先验证创作者／代理商工具付费＋佣金补充”的判断需要两处修正：

1. **截图／帖子转地点、地图收藏、共享清单已是竞争密集的基础功能。** Google Maps、Postlog、Mapstr、Mindtrip、Rhyme 等均有重叠能力，不能作为主要差异化。
2. **创作者工具也需要进一步聚焦。** Mapstr 已卖创作者地图，Beli 已卖餐厅指南订阅，Mindtrip 已提供创作者变现，byFood 允许创作者直接链接预约页获取佣金。通用“帮创作者卖清单”尚不足以形成优势。[Mapstr FAQ](https://en.mapstr.com/faq)、[Beli 创作者条款](https://beliapp.com/paid-guides-terms-creator)、[Mindtrip 变现说明](https://resources.mindtrip.ai/creators/creator-academy/how-to-earn-on-mindtrip)、[byFood 合作](https://www.byfood.com/affiliate-partnership)

优先验证的定位是：**帮助日本美食内容的维护者，把 SNS 中的餐厅线索整理成门店明确、来源可追溯、下一步行动清楚的资料，并降低持续更新的人工成本。** 潜在客户包括多账号餐饮营销代理商、美食媒体及高频维护清单的创作者；目前仍是假设，未证明这类客户足够多或愿意支付可持续价格。

## 2. 我们实际在竞争哪一段

| 用户任务 | 常见替代路径 | TabiTabi 需要证明的增量 |
| --- | --- | --- |
| 看到帖子，记住想去的店 | SNS 自带收藏、截图、笔记 | 少一次整理操作或避免线索丢失；基础保存本身价值有限 |
| 把帖子中的店放到地图 | Google Maps、Postlog、Mapstr、Tabi、Rhyme | 在信息残缺、同名分店等难例中更有效；日常简单例的效率也不能明显下降 |
| 整理并分享餐厅指南 | Mapstr、Beli、Mindtrip、共享地图 | 减少维护、纠错与查询工作，或带来可证实的行动增量 |
| 确认能否预约、从哪里预约 | 餐厅官网、Tabelog、Hot Pepper、TableCheck 等 | 减少选错分店、失效入口、把普通店铺页当预约页的错误 |
| 得到座位或完成预约 | 预约平台、AutoReserve、TABLEALL 等 | 当前只提供核对与行动入口；完成预约需要合作平台或新增执行服务 |

竞争包括用户已有的免费组合。即使没有一款 App 完全复制全部流程，用户也可能继续使用“帖子收藏＋Google Maps＋预约平台”。因此，对单款竞品功能数量的领先不足以证明商业价值。

## 5. TabiTabi 当前优势与短板

以下项目事实以当前 [README](../README.md) 和实现边界为基线，不把开发规格当已上线能力。

| 维度 | 当前项目事实 | 商业意义（判断） |
| --- | --- | --- |
| 日本餐厅核对 | 日语默认；分店需确认；帖子说法与已核验证据分开；预约、电话、官网、地图等入口有能力分类 | 有明确任务范围，适合建立同案例质量基准。尚未证明比竞品更准确、少步骤或更受信任 |
| 安全与信任 | 不把预约页面打开当预约成功，不从评分推断预约／排队规则；不确定时要求核对 | 避免关键错误是价值假设。保守提示过多也可能增加操作时间，应把质量和效率一起比较 |
| SNS 入口效率 | 现有动态帖子链接只识别平台，通常须补截图或店名；截图可上传，多餐厅可进队列 | 与声称直接分享帖子提取的竞品相比，当前入口摩擦可能更大。网页市场宣传不足以确定对方实测成功率 |
| 收藏与协作 | 有本机计划、历史和队列；账号／云同步／托管清单仍是后续规格 | 对手已有较完整保存／协作体验，消费者迁移理由不足；不宜通过补齐所有功能来解决定位问题 |
| 数据与交易 | 依赖 Places 等来源，输出第三方入口；没有自有席位库存和已证实交易收入 | 上游数据成本、平台变化和成交回传是依赖；地图数据提供方同时是用户替代产品 |
| 商业证据 | 已有流程及行动指标；本次未获取最新生产证据 | 识别完成、出站点击不能证明预约成立、获客增量、自然留存或付费业务成立 |

目前可积累的能力是经过人工确认的日本餐厅难例、质量回归、入口与来源核验方法，以及客户工作流程。只有这些持续提高结果、降低成本并被客户重复采用，才可能构成竞争优势。模型选择、提示词、确认弹窗、隐私承诺或“日本专用”的标签，单独都不足以证明难以替代。

持续维护业务还需验证数据交付方式：先限定客户真正需要的字段、更新频率和可接受的信息时效，逐字段确认来源的保存、展示和更新依据。Google Places 官方政策对缓存／保存内容有约束，Place ID 是可长期保存的例外；不能默认把 API 详情长期积累为自有资料库并导出给客户。可优先维护客户提供的线索、授权店方信息、自有核对记录和来源链接，但这些记录的具体字段仍需按来源确认。[Places API 政策](https://developers.google.com/maps/documentation/places/web-service/policies)

## 6. 分方向判断前景

下表是基于竞争和项目能力的定性投资判断，不是成功概率或收入预测。

| 方向 | 当前判断 | 最关键的成立条件 | 下一步投入 |
| --- | --- | --- | --- |
| 日本国内消费者截图／收藏订阅 | **偏谨慎**；免费替代多，使用频率和付费转化未证明 | 难例显著少错；简单例足够快；出现跨日自然复用，并在明确价格下选择付费 | 保持轻量入口，先比较任务结果及自然复用 |
| 日本餐厅信息维护工具／运营服务 | **最值得优先验证**，但客户规模与价格未知 | 客户反复维护多家餐厅，能量化节省工时／减少错误，愿承担持续费用 | 用运营协助交付验证，不先建完整 SaaS |
| 创作者通用地图销售平台 | **不适合作为当前主攻方向**；已有直接竞品和直接佣金路径 | 有独立分发、独家内容或明确日本核对／维护增量 | 将卖清单视为承载核对服务的选项，先访谈验证 |
| 日本预约佣金聚合 | **可以作为补充假设**；没有合同和成交回传无法估算收益 | 具备合作资格、有效流量、可确认结算，并覆盖分析／维护／获客成本 | 先分类出站；获批一个合作方后再验证完整经济性 |
| 面向国际访日用户的一次性服务 | **有需求背景，执行门槛较高**；属于独立客群验证 | 多语信息核对确有价值，有获客渠道和明确责任，单位服务成本可控 | 小范围访日需求访谈；不自动改变日本国内核心定位 |
| 全球通用旅行／预约平台 | **现阶段不建议投入**；竞争跨度和地域供给成本超出已证明能力 | 日本已有可复制的留存、付费、获客和合作供给模式 | 先建立日本单一场景证据，之后逐城市验证 |

访日需求背景确实可观：日本观光厅列 2025 年访日外国人旅行者约 **4,268 万**。这不是可付费用户数；不能直接乘套餐价格计算 TabiTabi 市场规模。[观光厅统计](https://www.mlit.go.jp/kankocho/tokei_hakusyo/shutsunyukokushasu.html)

国际化可先验证“海外客户使用日本餐厅服务”：已有语言界面和日本来源可以复用。扩展到海外餐厅则需重新验证门店匹配、平台和店方规则、合作资格及客服能力。两者应各自计算成本与成功指标。

从现有证据看，做成服务明确细分客户的小型盈利产品值得验证；形成大规模消费者平台的依据仍弱。竞争密集证明有人在提供类似方案，不能代替需求、盈利或增长证据。

## 7. 对已有开发清单的建议调整

本节记录研究时的建议；其后已经在 [开发清单](./next-feature-roadmap.md) 与 [模块设计](./feature-module-designs.md) v0.2 中落实取舍，并补充功能流程与验收。

| 原模块 | 本次建议 | 原因 |
| --- | --- | --- |
| M01 商业漏斗／自然复用 | 维持最高优先级；补同案例质量／耗时对比 | 需要证明相对免费替代的增量，避免只看自身完成率 |
| M02 用量／单位成本 | 维持最高优先级；计入人工核对、维护和获客成本 | API 便宜不等于业务毛利成立；影子计数仍不承担真实权益执行 |
| M04 具体价格／需求 | 维持最高优先级，明确哪类客户为何付费 | 竞品报价不能代替我们的付费证据 |
| M03 资料夹／批次 | 先做完成验证所需的最小恢复与管理 | 通用标签／收藏扩建容易进入功能追赶，应由真实任务摩擦决定 |
| M05／M07 清单／工作台 | 聚焦餐厅核对、失效纠错、来源时间与维护报告；先运营协助 | 泛策展与创作者变现已拥挤，自助权限系统不应先于客户需求 |
| M06 出站／佣金 | a：分类和测量可先做；b：合作账本继续保留门槛 | 普通跳转不是有效归因，更不是收入 |
| M08–M13 账号、社交、提醒、支付、商家、原生入口 | 依有效需求触发，不作为一轮全部开发任务 | 使用和付费价值尚待证明；增加基础设施无法替代价值验证 |
| M14 游客服务 | 单独建立需求、渠道和单位成本证据 | 国内自然复用与游客一次性消费口径不同 |

建议下一轮产品主线：**同案例效果比较 → 高频维护者需求与价格 → 运营协助交付 → 确认可持续经济性 → 再扩建自助功能。**

## 8. 一轮可改变判断的验证

以下人数和阈值是建议预先约定的探索性决策标准，并非现有结果、统计显著性承诺或付费调用授权。试验开始前确定比较对象在日本／参与者设备上的可用性，及哪些操作会产生费用。先使用已有、经人工确认的案例；新增付费 API 或购买竞品需另行确认明确额度。

| 验证 | 方法 | 建议继续条件 | 未达到时的决策 |
| --- | --- | --- | --- |
| 质量与效率 | 10–15 位目标用户，至少 30 个去重案例，含常规和分店／失效／预约难例；任务分配交叉平衡，避免同人反复做同案的学习效应。比较 TabiTabi 与用户常用“Maps＋官网／预约平台”，可用时加入 Postlog 等直接工具；预先统一任务时间上限 | 两条继续路径都须满足：全任务正确完成率不下降、没有新增关键误导。其后满足其一：成功任务中位耗时降低 ≥25%；或预定义难例的关键错误减少、常规成功任务中位耗时增加不超过 10%，且用户愿重复选择。分别报告成功率、未知／弃权／超时率及成功任务耗时，失败保留在分母 | 增量弱或安全条件未通过时，减少通用 App 投入，先修复明确失败；不得通过只统计成功任务或大量拒答宣布领先 |
| 自然复用 | 完成首次真实任务后不布置复用任务、不催回访；按 M01 观察 ≥24h 至第 7 日的不同会话复用；至少两批独立招募，各观察 10 位以上同意测量的参与者 | 预先选择例如 ≥30% 的探索门槛，且两批均出现自然复用；同时记录分母、选择偏差和区间，不因小样本宣布 PMF | 复用不足时优先评估一次性／业务场景，不急做消费者月订阅；测试期不足 7 日不得下结论 |
| 业务客户 | 访谈 5–8 位负责多家餐厅／多账号内容维护的人，要求提供最近真实流程与工时；对 3 个匹配者提出同一明确范围、交付方式和价格的试点，同时核实字段、更新频率及来源交付可行性 | 至少 2 位接受明确价格并提供任务可进入试点，仍只算意向。扩建自助工作台前，至少 2 位实际付款、验收，并完成至少一次按该价格续购；记录真实节省工时和错误。执行收费须遵循项目已有授权边界 | 只有口头同意、免费任务或继续意愿时，不称付费验证通过；来源不能支持交付时，调整字段／交付方式后再验证 |
| 单位经济性 | 以一次完整交付／客户周期为单位，记录真实供应商账单归属、首次和重复核验的人工分钟、客服及渠道成本；佣金仅按合作方确认的有效结算记录 | 已收价格在保守成本情形下有正贡献，并发生该价格下的实际续购；若只是运营协助服务，明确人工交付占比 | 毛利依赖未证实佣金或不计人工时，调整报价／流程／客户，不靠扩大免费调用弥补 |

“正确行动”需人工真值：正确门店及分店、当前已核验入口、清楚理解预约／请求／电话／候位的区别。无法核实的营业或预约状态标为未知。出站、收藏、点击和主观好评分别记录，不能合并成“预约成功”。

这轮验证可以按 4–6 周规划：先定案例与比较口径，再完成任务比较和访谈，最后观察满 7 日复用并评估两次业务交付。具体工期取决于招募与客户任务，不是开发交付承诺。本报告未实际招募、联系客户、收费、调用付费识别或部署。

## 9. 证据不足与可推翻结论的条件

- 未进行竞品同案例实测；不能断言对方没有证据核对，或 TabiTabi 比对方安全／准确。
- 商店 SKU 和公开收费是报价，不代表当前用户购买价、销量、留存或盈利。多个 SKU、地域和历史版本差异已在相关条目标明。
- 未掌握最新 TabiTabi 生产 cohort、真实客户合同、结算、成本及 CAC；因此不作收入预测、估值或成功概率。
- 所查日本与国际产品足以证明核心功能重叠，但不是全市场盘点；地方服务、新版本与未公开商务能力可能改变比较。
- 如果任务比较证明显著增量，两批出现自然复用，并取得可持续价格下的实际付款和续购，判断会向积极调整；若优势只在演示案例、用户没有复用、客户不接受价格，建议收缩投入。消费者复用和业务客户付款分别支撑各自方向，不混合成同一种商业验证。

**当前决定：先用质量、效率和付费交付证据决定做多大；把日本餐厅核对这一具体工作做清楚，再决定扩展市场。**

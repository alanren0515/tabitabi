# 本地发布审计流程

这套流程用于完成发布门槛中的 30 例实机审计和 30 个风险场景。它不会把单元测试自动转换成人工通过记录。

## 启动工作台

```bash
npm run audit
```

然后在同一台 Mac 打开终端打印的地址，通常是 `http://127.0.0.1:4174/audit`。如果 4174 已被占用，启动器会自动尝试后续端口。审计接口必须显式绑定环回地址；普通 `npm start` 和生产容器不会启用它。每次写入都会先校验字段，再原子更新 `eval/manual-audits.json` 或 `eval/coverage-matrix.json`。未完成草稿只保存在当前浏览器。

需要在真实手机上执行时，让手机与 Mac 连接同一个可信 Wi-Fi，然后运行：

```bash
npm run audit:mobile
```

终端会列出带随机令牌的局域网 URL。在手机浏览器打开其中一个 URL；首次打开会建立一个最长 4 小时的 `HttpOnly`、`SameSite=Strict` 审计会话，页面随后立即从地址栏移除令牌。令牌每次启动都会变化，停止进程后旧令牌失效。局域网模式下所有 API（包括视觉与 Places 请求）都要求这个会话；不要把 URL 发给别人，也不要在公共 Wi-Fi 使用。结束审计后在终端按 `Ctrl-C`。

审计页顶部会显示当前是“Mac 本机审计”还是“手机 · 可信 Wi-Fi 会话”。手机会话期间让 Mac 保持唤醒并保留启动命令所在的终端；如果页面提示会话失效，停止旧进程后重新运行 `npm run audit:mobile`，再打开新地址。带令牌的审计入口响应使用 `no-referrer`，随后也会从地址栏移除令牌。

工作台顶部同时显示只读的真实试运行面板：live 输入、有效反馈、分析完成率、行动率和有帮助比例。它直接读取当前事件日志，自动排除审计、演示和旧版事件；“刷新数据”不会写入评估文件，也不会把审计操作计入试运行。

手机若无法打开页面，先确认两台设备位于同一网络，且 macOS 防火墙允许 Node 接收入站连接。不要为了省事把审计端口暴露到公网或在路由器上做端口转发。

## 需要用户提供的 SNS 素材

不需要为 30 个发布样本再准备截图：完整人工移动端审计已经达到 30/30。全部 33 个确认案例中，后来加入的 3 个真实视觉案例仍为“仅决策已核对”，可以继续做真机补充审计，但不影响 30 例发布样本门槛。风险矩阵目前另有 2 个截图场景尚未完成。

为补齐现有风险矩阵，准备以下 2 张来自公开帖子的截图：

1. 小红书：主观评价和店名、价格、地址等客观事实混在一起。
2. 小红书：旧帖子，餐厅后来搬迁、改名或关闭。

建议第一张只提交截图；第二张截图加一句当前店名或地区，并附公开帖子 URL、约发布日期和你认为的当前状态。不要一次上传多张图片。

X 临时休业、Instagram 低清/无店名/仅车站、TikTok 同名分店/单图六餐厅和电话确认话术场景已经完成真实流程。风险场景页现在默认只显示未完成项目，并会按每个标签列出素材与操作要求；页签数量会跟随 `eval/cases.json` 和 `eval/coverage-matrix.json` 动态更新。

只使用公开页面。不要提交私信、通知、私人账号或包含无关个人信息的评论区。证据 JSON 只记录匿名案例 ID、公开官方 URL 或本地截图路径，不保存原帖正文、创作者账号或原始截图内容。

## 每例必须检查

1. 使用 `npm run audit:mobile` 在真实手机打开工作台，再点击“在主产品打开此输入”。
2. 核对候选餐厅身份、城市、分店和地址。
3. 核对结论是预约、排队、到店登记、电话确认还是信息不足。
4. 确认没有把平台店铺页、申请预约、候补或代订服务说成“预约成功”。
5. 打开主要行动按钮，确认它进入正确平台和正确餐厅；不要完成付费或最终提交。
6. 检查手机页面没有按钮遮挡、横向溢出或无法返回。
7. 保存一张不含私人信息的结果页证据，并在工作台填写判断。

如果七项检查全部没有问题，可点击“检查无问题，填入通过项”，再上传结果页证据并选择“写入并下一例”。该按钮只减少重复选择，不会自动生成证据或绕过必填项；任何一项有问题时应逐项填写，并从“有问题”筛选中复查。

工作台允许手机直接上传一张 PNG/JPEG 结果页截图，并自动把返回的本地路径加入证据字段。上传前必须确认它只是本产品结果页，不含原始 SNS 帖子、用户名、评论、私信、通知或 API Key。证据最大 4 MB，保存在 Mac 的 `output/manual/`，该目录被 Git 忽略、不会进入生产镜像，也不能经静态 HTTP 路径读取。原始 SNS 截图仍只用于当前视觉请求，不要通过证据上传功能保存。

截图来源案例不会用 `query` 预填来冒充截图审计；工作台会打开空白主产品首页，并明确要求从手机相册上传对应原图。文字案例才会使用审核用的预填输入。

主产品接受 PNG、JPEG 和 WebP，最大 8MB。iPhone 系统截图通常是 PNG，可以直接使用；如果相册素材是 HEIC/HEIF，请先重新截图或转换成上述格式。桌面审计时也可把支持格式的截图直接粘贴到餐厅线索输入框，补充文字会同时保留。

`mobileFlow: pending` 只会生成 `decision_audited`，不计入 30 例完整发布样本。手机流程完成后，无论结果通过还是失败，都应选择对应的 `pass` 或 `fail`，由门槛真实反映问题。

## 复核门槛

```bash
npm run eval:validate
npm run eval:candidates
npm run eval:decisions
npm run eval:release-gate
```

`eval:decisions` 会产生真实 Places 和可选数据源调用；它生成的决策安全报告必须覆盖全部当前确认案例、逐项通过且不超过 7 天。只有真实证据补齐后才将风险场景从 `planned` 改为 `confirmed`。工作台可以导出两份 JSON 作为备份，但正常本地流程可直接写入仓库中的评估文件。

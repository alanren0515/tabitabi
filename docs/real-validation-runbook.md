## 4. 30 个有效案例、三路线、90 任务的平衡分配

必需路线名称为 `baseline`、`candidate`、`primaryReference`。唯一主替代路线默认 Maps＋官网／预约平台，具体操作路径、设备／地区可用性在采集前冻结；直接竞品仅作次级诊断，不能用有利竞品替换主路线。

以下方法适用于参与者人数 N 为 10–15 的首轮最小 30 个有效案例。先冻结案例顺序和 normal/hard 配比，可事前在各层内打乱顺序；不使用任务成绩重新排序。正式匿名参与编号与内部索引的映射留在受控研究域，不含真实身份。

1. 将参与者的内部索引记为 P0…P(N−1)，案例索引记为 C0…C29，令 `s = floor(N / 3)`。这些是排程索引；正式 `participantCode` 使用 `P-` 加 3–32 位随机字母／数字／下划线／连字符，人工审核编号使用相同规则的 `R-` 前缀，不把 P0 直接写进任务文件。
2. 案例 Ci 的 baseline 分给 `P(i mod N)`；candidate 分给 `P((i + s) mod N)`；primaryReference 分给 `P((i + 2s) mod N)`。N 为 10–15 时三位始终不同，每案三路线各一条任务。
3. 为每位参与者按路线建立三个任务队列。Pj 的首路线取 `[baseline, candidate, primaryReference][j mod 3]`，之后按这个起点循环取各路线一项，空队列跳过，直到本人的队列为空。
4. 给每位参与者从 1 开始填写 `assignmentOrder`；同一参与者按此顺序串行执行，实际时间不能重叠或倒置。培训用不同的非正式案例，正式任务不讲出目标分店或正确行动。
5. 核对同案参与者互不重复、每路线 30 项、总计 90 项；每位参与者三路线任务数差 ≤1，首路线人数差 ≤1。若人数或案例有效性改变，重新核对分配与版本，不只在表格里写 `routeOrderBalanced=true`。

| 安排示例 | 每位路线任务数 | 每位正式任务数 | 首路线人数 |
| --- | --- | --- | --- |
| N=10、s=3 | 每路线 3 项 | 9 项 | baseline 4、candidate 3、primaryReference 3 |
| N=15、s=5 | 每路线 2 项 | 6 项 | 各 5 人 |

为所有参与者准备一张排程表：

| 匿名参与编号 | assignmentOrder | attemptId | caseId | route | revision | deviceCode／region | 计划时段 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 待指定 | 待分配 | 待分配的唯一 ID | 冻结 caseRoster 中的 ID | 三条必需路线之一 | 冻结的对应版本 | 待核验 | 待指定 |

**统一 5 分钟／300 秒是首轮待冻结建议。** 若采用它，最小 90 项需预留合计 `90 × 5 = 450 分钟 = 7.5 小时` 的最大任务窗口；超过 90 项则增加相应窗口，提前终结会减少实际任务时间。培训、休息、排程、案例准备、人工评分／复核和协调另计，7.5 小时不是工期承诺。不同参与者可由适当主持安排独立会话；同一参与者不并行做任务。

## 5. 人工真值与评分准备

1. 真值负责人用获准的公开线索或受控案例材料识别具体门店与分店，分别核对身份、营业／规则、入口及适当行动。仅有线上入口不证明空席或预约成立。
2. 每案记录 `caseId/groundTruthVersion`、normal/hard、text/screenshot/url、restaurantId／branchId、`actionable` 或 `unknown_required`、`expectedAction`，人工审核编号、确认时间、来源类型／引用／核验时间、`validFrom/validUntil`。真值有效窗口应覆盖冻结研究起止窗口，来源证据先于人工确认，确认先于协议冻结。
3. 确认至少 30 个有效去重案例。普通用户截图不自动成为评测集；未获授权或核验不足的案例不能冒充有效真值。分层和难例定义事前冻结，不按 candidate 错误事后挑难例。
4. 人工审核者按冻结 rubric 读取实际结果：确认选择的分店、下一行动和限制理解；记录 `reviewerCode/reviewReason/reviewStatus`。不确定评分先复核，未确认就保留缺口；不用 Qwen／OpenAI 或模型投票升级为真值。
5. 真值失效标记 `invalid_truth` 和原因，三路线对称排除，保留原名单、分配总量及排除数。有效案例不足 30 则 GQ 证据不足；额外重试或替换研究须按新协议／单独记录处理，不能覆盖原失败。

| terminal | 人工评分口径 |
| --- | --- |
| `correct_action` | 真值可行动；选中正确 branchId 和 expectedAction；分店确认及行动理解都成立 |
| `justified_unknown` | 真值预定 `unknown_required`，正确理解未知；选择 unknown，无错误分店或行动 |
| `incorrect_unknown` | 可行动案例被拒答／未解决，或未知理解不符合真值 |
| `wrong_branch`／`unsafe_action`／`wrong_action` | 按 rubric 记录具体分店／限制／行动错误；关键错误不被速度或点击掩盖 |
| `abandoned` | 参与者退出，记录实际终止时刻与原因，不重置计时 |
| `timed_out` | 在冻结统一上限到达时停止，记录计时器到达上限的终止时刻；不继续补做 |

字段缺失／无效和 `incomplete_attempt` 独立报告，不默认成功。`correct_action` 和 `justified_unknown` 不是由参与者自报或 HTTP 成功自动成立。

## 6. 主持与任务记录

### 开场说明（日文草稿）

> 今日は、飲食店の店舗・支店を確認し、適切な次の行動を選ぶ方法を比較します。あなたの能力を評価する調査ではありません。課題が表示され、入力できるようになった時点から、結果を提出するか、中止するか、制限時間になるまで計時します。
>
> 店舗や支店、次に何をするか、分からない点を、最後に説明してください。情報が足りない場合は、そのまま分からないと答えて構いません。予約、電話、購入は行いません。途中で中止できます。操作が止まった時も、時間を戻してやり直すことはありません。
>
> 操作結果、時間、利用した方法と端末の区分を匿名の番号で記録します。氏名やアカウント情報、私的な画像は記録しません。記録の範囲と保管期間は説明した内容に従います。疑問がある場合は、課題の開始前にお知らせください。

主持在实际采集前确认同意说明和设备／地区。用非正式案例演示“结果提交／停止”的方法；对三路线提供一致的程序说明，正式任务中不提示正确分店、来源或下一动作。

### 每项任务的开始与终结

- 展示冻结任务并允许输入时同时开始计时，记录 `startedAt`。计时包含输入／上传、确认分店、纠错和选择行动，不从 API 返回时才开始。
- 参与者提交可判断的终结结果时记录 `endedAt`，询问已选分店、下一行动和理解的限制；外部点击本身不算成功，不实际完成预约。
- 参与者退出记录 `abandoned`；统一上限到达立即停止并记录 `timed_out`。不暂停后重置、删失败或让额外重试覆盖原任务。
- 分配后路线故障标 `routeAvailability=failed_after_assignment` 并记录原因，不能标成功。分配前不可用先记录和处理，不能只比较可用路线后宣布通过。
- 开始／结束用 UTC ISO 时间；每位参与者的顺序与实际时间一致，结束晚于开始。超时任务长度应等于冻结的 timeCapSeconds，不事后补造时间。

一项一行记录，下面是主持表的字段布局，不是可直接输入 CLI 的新增 schema；完成后整理为现有 `protocol/groundTruth[]/attempts[]` 契约。

| 字段组 | 开始时记录 | 结束／评分时记录 |
| --- | --- | --- |
| 唯一关联 | attemptId、caseId、participantCode、assignmentOrder | 保持原 ID，重发不另造任务 |
| 版本与路线 | protocolVersion、groundTruthVersion、rubricVersion、route、revision；真实记录 evidenceClass=`human_study` | 校核无中途混版；不得将 synthetic 改标签充当真实输入 |
| 设备与可用性 | deviceCode、region、routeAvailability | 故障更新为 failed_after_assignment，另记受控原因 |
| 完整任务计时 | timingScope=`task_display_and_input_to_terminal`、startedAt | endedAt；弃权／超时终止时刻；不填虚构零耗时 |
| 实际选择 | 待提交 | selectedBranchId、selectedAction、branchConfirmed、actionUnderstood；未知如实记录 |
| 人工审核 | reviewerCode 待指定 | terminal、reviewReason、reviewStatus=`confirmed` 仅在人工实际确认后填写 |

允许写入 JSON 的字段、编号格式和真实／合成 evidenceClass 以 [研究输入契约](./benchmark-protocol.md#研究输入契约) 及仓库 fixture 的结构为准；fixture 只示范格式，不能复制其内容或只改 `studyMode`。

## 7. 结束后用离线工具校验和判定

仅在真实输入已获授权并位于受控本地研究域后，显式指定一份研究文件；默认命令读的是 synthetic，默认成功不能证明真人验证。以下路径是占位位置，实际路径不放公开报告。

```sh
npm run benchmark:baseline -- --verify
npm run benchmark:validate -- --input /absolute/controlled-research/study.json
npm run benchmark:summary -- --input /absolute/controlled-research/study.json
```

离线命令不联网、不调用供应商、不写产品事件；研究 JSON 上限 5 MB。真人模式还核对实际旧版档案与禁用供应商的配置。validate 只验证结构，一份包含占位值或未完成任务的准备表不能通过后宣称研究完成。

研究负责人复核工具报告中的实际人数、同一有效案例三路线覆盖、版本／时间、原分配分母、排除、未知／弃权／超时、关键错误和成功耗时样本。缺记录不从分母删除，额外重试不补原记录；任一必需路线、任务时间或真人 baseline 证据不足则保留 `insufficient_evidence`。

GQ 仍按原门槛：candidate 对 baseline 和 primaryReference 的两种完成率不下降、无新增关键误导；再对 primaryReference 满足成功中位耗时降低 ≥25%，或难例关键错误减少且常规成功中位耗时增加 ≤10%。不改变阈值，不据结果换主路线。完整 synthetic 结果只能为 `fixture_only`；真人未通过、证据不足和通过分开记录，退出状态 0 不等于公开发布许可。

产品负责人把结论、冻结版本、缺口和本次允许投入的范围写入受控复核记录，再按 [进入包](./next-stage-entry-pack.md#7-19-个-bcd-任务的解锁范围) 选择下一步；不自动投入全部 B/C/D。研究规模只支持探索判断，不证明预约成立、市场留存或商业成立。

## 8. 最小字段、保留与研究流量隔离

| 数据 | 保存范围与处理 |
| --- | --- |
| 匿名准备盘点 | 人数范围、任务类型、设备／地区类别、安排状态；不收实名、联系方式、客户内容或支付资料 |
| 参与者与研究记录 | 随机／不透明参与编号、目标资格、同意范围、设备类别、任务与时间／评分；不使用邮箱或账号作为编号 |
| 案例和真值材料 | 只保存已获授权、支撑具体真值的最小材料和受控引用；不收私人 DM／账号凭证，不保存普通用户截图作为评测集 |
| 联系资料（如以后需要） | 仅在外联授权与本人同意后独立受控保存，联络范围／用途／保留另行确认；不写入任务文件、匿名日志或公开文档 |
| 业务访谈 | 记录匿名角色、任务／工时、许可缺口、报价版本与回应；真实客户资料另有任务授权和字段许可，不与产品事件混存 |
| 原始研究记录 | 默认最多 30 天，实际到期及清理责任人在启用前落实，当前均待指定；自动删除尚未实现 |
| 不可反推匿名汇总 | 最多 90 天，不输出参与者／案例编号、源内容或审核正文；保留到期清理记录 |

清理负责人在实际采集前登记受控位置及到期安排，到期检查并清理原记录／副本，记录完成或缺口；不因汇总保存 90 天延长原始材料期限。未落实人工清理不能写成已自动执行。

benchmark、招募研究、任务、报酬、提醒以及业务维护均保持研究身份和存储域隔离，不进入自然 R7 cohort。正常产品流量的自然来源资格未知时单列，不把这轮任务完成当自然复用；GR 仍需两批独立真实成熟自然 cohort 的证据。

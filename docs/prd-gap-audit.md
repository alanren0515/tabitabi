## 与原 PRD 不同但有意收紧的地方

- 不从评分、评论数、社交互动或“热门区域”推断必须预约；只有明确预约入口或官方规则才产生可操作结论。
- 不编造“开店前 20–30 分钟到达”一类时间。只有已核验官网明确给出排队/到店规则时才展示原文；等待时间保持未知。
- Tabelog 首版只做 URL 类型识别、合规跳转与请求预约边界提示，不抓取评分、评论、库存或结算内容。
- Hot Pepper API 命中只证明店铺信息匹配，不证明网络预约开放；明确 `/yoyaku` 路径也仍需平台最终确认。
- 实时餐厅长期只保存 Place ID 和用户自己的线索/计划；重新打开时刷新第三方详情。
- 没有平台库存合作权限时，TabiTabi 是行动导航层，不是代订方，也不接收第三方账号或支付资料。

## 下一步顺序

1. 保持 Codex 内置浏览器 `390×844` 为日常审计视口，并用真实 iPhone Safari 抽查文件选择、软键盘、返回和第三方跳转；不要影响用户的 Chrome 会话。
2. 依次完成 Hot Pepper listing/预约、Tabelog listing/网络预约/请求预约、Gurunavi 和 Reserve with Google 的真实移动端跳转与返回流程；TableCheck 官网直链已由六本木案例通过。2026-07-16 已完成 9 个退出登录的 1280×720 公开导航检查并据此补上 Tabelog 当前 `/booking/form/new` 规则，但这些桌面证据不冒充手机审计，仍需 390×844 或真实 Safari 复验。
3. 以日本国内、日语使用者为主开展小范围测试，优先收集 Instagram/TikTok 输入；YouTube Shorts、X、LINE 分享作为补充来源，游客和中文用户只进入兼容性样本。
4. 本地开发可运行 `npm run pilot:gate`；Fly 正式试点必须运行 `npm run release:pilot-remote`，最后运行 `npm run release:formal-gate`。门槛为 20 次生产 live 输入、10 次反馈、分析完成率 ≥80%、行动点击率 ≥35%、有帮助比例 ≥60%。保存率和无用户标识的 7 日回访下界同时报告；没有真实生产样本前不宣称达到 PRD 商业验证指标。

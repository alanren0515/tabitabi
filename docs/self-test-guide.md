# 部署后个人自测手册

日期：2026-10-03  
当前状态：本机准备；待付费评估、冻结版本与部署预检，尚未部署本轮 A01–A12。本文供部署后按实际版本执行，不表示线上已具备全部检查项。

这轮自测检查你自己能否理解、纠错、保存和恢复餐厅任务。它不能替代目标用户研究、正式商业验收或公开发布门槛；单人结果不能通过 GQ/G1/GB/GR。正式研究使用 [真实验证手册](./real-validation-runbook.md) 和 [下一阶段进入包](./next-stage-entry-pack.md)；发布另遵守 [人工审计](./manual-audit.md) 与 [公开发布检查表](./formal-public-release-checklist.md)。

## 2–3 分钟开测

1. **使用专用测试存储环境。** 建议普通、独立的浏览器配置文件，避免清掉个人计划。测试与日常使用在同一浏览器配置文件、同一站点下共享 `localStorage` 的保存、历史和队列；这些记录不会持久保存 audit 标签。隐身模式或浏览器存储限制可能无法保存，先如实记录限制。
2. 在要测试的设备打开 [闭门测试入口](https://tabitabi-jp.fly.dev/?audit=1)，确认页面显示测试模式提示。首次未见提示可联网刷新一次，让离线页面更新；仍没有提示就记录版本未包含并暂停真实核对。同一标签页的导航和刷新继续使用该标记；新标签页须重新打开带 `audit=1` 的链接。标记通常放在 `sessionStorage`；无法写入时，页面保留 URL 的 `audit=1` 并继续在导航中携带它。发现标记消失，先重新打开入口，暂不发起真实核对。
3. 打开“设置 → 查看运行信息”，记录“测试版本”和供应商可用状态。版本来自 `/api/capabilities` 的 `releaseRevision`；未知就填“未知／待维护者核对”，不能填本机 HEAD 或猜一个 40 位版本号。`/readyz` 用于就绪／降级状态，不用于确认版本。已有邀请码可用于解锁，但不要写入记录或截进证据。
4. 复制 [自测记录模板](./self-test-record-template.md)，先执行 ST01–ST08。ST09–ST15 只有在实际部署支持、素材已核对且真实调用获批后执行；未执行保持“未执行”。

测试模式只将流程排除出试点／自然使用统计；它不免除邀请码和真实供应商费用，也不保证网络请求完全不记录：成本和异常记录仍可保留。线上 `/audit` 工作台不可用，它只在本机／可信局域网启用，生产镜像不含审计素材。不要为自测修改 `PUBLIC_RELEASE_MODE`。

## 开始前准备

准备少量你熟悉、能人工核对的餐厅：一家具备明确官方资料的店、一组同名不同分店的店，以及一个信息不足或旧帖案例；多店恢复可复用这些素材。为每案记下匿名编号、官方店名／分店／地址、官方来源链接和核对日期。无法确认的内容填“未知”，不要把模型输出或虚构资料当真值。营业、迁址和预约规则可能变化，测试当天重新确认关键内容。

也可先用已准备的 [三个公开自测案例](./self-test-case-pack.md)：六本木店、渋谷同品牌分店和不可预约的目标店。包含可复制文字、官方核对链接及截图范围；开测时仍由你确认当前真值，不预填通过。

文字只用公开店名和地点线索。截图只选公开页面，先裁掉账号头像、用户名、私信、通知、无关评论和其他个人信息；保留足以核对店名／分店的内容。使用 PNG、JPEG 或 WebP。测试记录不另存原图；回传证据只用裁净的产品结果页，不能附原始 SNS 截图、邀请值或密钥。

真实核对可能调用 Qwen、OpenAI fallback、Google Places 和 Hot Pepper；一次用户操作可能包含搜索、详情、预览、失败重试或 fallback。执行前由维护者核实当前官方计费并确认下表，数值留待审批，不能把服务端每日硬上限当作本轮授权额度。

| 真实调用准备项 | 本轮待确认 |
| --- | --- |
| 供应商、API 操作与目标版本 | 待填 |
| 官方价格来源、核实日期、单位与币种 | 待填 |
| 每类操作最大次数，含失败／重试／fallback | 待填 |
| 一次性、每月固定、按量估算与最大费用暴露 | 待填；未知不填 0 |
| 已批准的金额／调用上限和批准引用 | 待填 |
| 停止条件与核对负责人 | 待填；达到本轮上限、服务预算受阻或费用无法界定时停止 |

未批准时只做示例与本机检查。不要为了测试预算提示人为耗尽额度，也不要绕过限流、换标签页重复调用或自动重试。范围、供应商或额度改变时重新确认。

## 检查清单

操作名称以实际部署语言为准；没有对应功能时先核对版本，再记“不适用／版本未包含”，不能以未看到功能认定通过。

| ID | 操作 | 预期与记录重点 |
| --- | --- | --- |
| ST01 | 打开免费操作示例，走完输入、候选、结果和返回 | 一直能认出示例／虚构信息；结果按钮仅本地模拟，不拨号、不打开外页、不发起预约。不能误作真实餐厅事实。测试模式提示可见。 |
| ST02 | 将示例保存为两个不同计划，修改自己的进度 | 计划分别保留；“本人已预约／已去过”等是你的记录，不改变系统建议，也不产生预约。 |
| ST03 | 用店名／自己写的备注搜索；编辑备注、日期、时间与人数 | 能找到对应计划；修改后保留，搜索／编辑不触发真实核对、不伪造来源更新时间。 |
| ST04 | 在想去／最近确认／稍后确认列表中分别点导出，检查实际文件或可见内容 | 名称／备注／计划等许可字段可读，不含原图、密钥或完整第三方快照。分别记录“成功下载文件”与“仅看到内容／手动保存”，后者不能算下载通过。 |
| ST05 | 在专用测试环境展开“管理列表”，分域清空记录，马上撤销 | 仅选中域受影响，其他域不被误删；撤销后恢复。普通空列表不显示清空；删除最后一项仍可撤销。存储异常先重试／导出，不当作没有记录。确认范围后操作，不用个人唯一副本测试。 |
| ST06 | 导航返回和刷新页面，查看已产生的本机记录 | 保存、历史和队列按实际存在内容恢复；测试标记仍在。存储失败须有提示，不能把内存暂存说成刷新后可恢复。 |
| ST07 | 切换日文、英文、简中；在手机窄屏检查主要按钮和返回 | 操作可理解、无遮挡或横向溢出；示例／真实、分店确认、未知与行动限制均清楚。店名和来源原文可以保留原语言。 |
| ST08 | 页面已联网加载后断网，查看已保存列表，再恢复网络 | 可读已缓存的本机资料；新搜索／识别明确需要联网，输入不丢、不持续重试。首次离线未缓存页面无法打开需单列，不能作为已验证离线启动。 |
| ST09 | 在获批范围内输入熟悉餐厅的文字线索 | 人工对照官方店名、分店和地址；由你确认候选后才继续。选对店与打开行动入口分开记录。 |
| ST10 | 在获批范围内上传裁净的真实截图 | 对照图片修正店名／地点，再明确确认；帖子主张、感想与官方事实区分，识别错误不应直接成为预约建议。 |
| ST11 | 使用同名分店／不足线索案例，补地区、分店或地址；必要时返回改选 | 缺线索时允许未知或要求补充，不擅自选分店；更正应影响后续结果。补线索／重查仍计入已批调用范围。 |
| ST12 | 查看真实结果的本次生成、来源获取和复核时间 | 生成时间不冒充来源刚更新；未知时间明确未知，缓存不凭读取时间变“刚获取”。时间不保证当前营业、空席或预约成立。 |
| ST13 | 打开官网／地图／预约等行动入口，核对目标餐厅与分店，然后返回 | 入口、申请、候补和店铺介绍正确区分；只打开查看，不下单、付款、提交预约或拨出电话。产品不能说“预约成功”。 |
| ST14 | 保存一个真实计划；先只打开／刷新，再显式点击重新核对 | 只阅读或恢复不自动付费核对；显式操作受本轮预算约束。只有真实终结结果才更新复核元数据，失败不伪装完成，也不改变你的进度。 |
| ST15 | 从获批的多店素材建立队列；完成一店后暂停、刷新，再主动继续下一店 | 当前／待处理／失败状态可理解，已完成内容保留；暂停／刷新不自动处理整批，不无提示重复扣调用。仅做获批的下一店，余项可保留待处理。 |

ST09–ST15 可复用一次真实结果，避免为每个观察点额外请求。真实调用在预算上限、服务预算耗尽、安全停止或无法界定费用时停止；已存资料仍可检查。报价卡默认关闭、没有自然 campaign，A12 协作仍为 fixture；本轮不测试付款、真实套餐权益、客户协作或自然留存，也不把它们当作已上线功能。

## 怎么判断与回传

- **通过**：实际执行，且该项预期有证据支持。**失败**：行为与预期不符。
- **符合预期的受阻**：断网、无匹配、信息不足、预算／安全停止等被清楚说明且输入／资料安全；这证明失败处理，不证明真实任务完成。误导性结果或丢数据仍记失败。
- **不适用**：实际版本没有功能或案例不具备条件，写明原因。**未执行**：未获批准、时间不足或尚未操作，默认保持该状态。

问题按影响记录：P0 为错误分店或行动造成现实风险、私密数据泄露、未经操作的真实调用等，立即停止受影响流程并通知维护者；P1 为主流程不可完成、无法保存恢复、误删／导出丢失或测试标记失效，暂停相关项；P2 为不阻断任务的文案、布局或次要体验问题。不要自行改生产配置或重试高风险操作来收集证据。

回传最小信息：测试 ID、实际部署版本、设备／系统／浏览器、语言和时间、匿名案例编号、简短复现步骤、预期／实际、结果及 P0/P1/P2、已裁净的产品页证据、费用已知／未知与剩余授权情况。不要回传邀请码、个人联系信息、私信、原图、完整搜索输入或原始网络日志。

结束后按模板统计通过、失败、受阻、不适用和未执行，列出未验证范围。供应商账单尚未显示时填“未知／待出账”，已有用量估算则明确写“估算”及依据，不能填零。保留必要的匿名记录，清理专用环境中的测试资料；这份记录只支持个人部署后自测，不构成正式商业验收或发布许可。

维护者的当前部署检查、费用依据与待补条件见 [自测部署准备状态](./self-test-deployment-readiness.md)。

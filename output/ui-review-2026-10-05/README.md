## 按文章顺序审查

1. **任务**：首页同时支持截图和店名，但结果页的“保存”藏在“其他操作”中。稍后确认只在页脚，个人任务三种入口（历史/行きたい/确认待）关系未解释。建议按“新查店—继续确认—计划到店”明确组织。
2. **风险与优先级**：候选确认做得好。结果页先显示预约/拨号，再显示确定性和结论。建议主行动同一区域先显示“门店已确认/哪些未确认/下一步不代表预约成立”的最小边界，详细来源继续折叠。
3. **灰度层级**：主按钮突出；但收藏页搜索、导出、清空近似等权。删除应降级，空态应突出添加。首页三步既像进度又在下方重复介绍，建议只留一份明确标为说明的流程。
4. **移动重排**：390宽无横向溢出；文字输入与提交落到首屏下方，820宽标题与上传区纵向距离过大。应缩减介绍、上传占位高度，或提供截图/店名输入方式切换，而非整体缩小文字。
5. **视觉系统**：日文明朝标题、深蓝操作色、浅底及珊瑚强调形成统一气质，应保留。页脚原生蓝链接和列表工具按钮样式与主流程不够统一；说明过多使用10–12px小字，不能靠降低对比度来表达次要性。
6. **状态**：收藏空态没有下一动作；待确认空态显示清理、导出、清空。“情報を確認中”是unknown静态结论（src/i18n.js），建议改为“情報を確認できませんでした”或“店舗への確認が必要です”，仅真实请求中使用“確認中”。示例提示重复但虚构电话号码仍可拨号，应以不可外发的模拟交互代替。没有拨号验证。
7. **可访问性**：结果确定性12px，computed color rgb(82,107,115)，父status-row opacity .82，白底有效颜色约rgb(113,134,140)，计算对比度3.836:1，低于普通文字4.5:1要求。不要把风险提示与禁用态视觉混用。首页导航按钮44px、折叠summary44px是优点；移动图标虽有ARIA标签，仍有首次使用理解成本。样本页面控制台未见error，不构成完整键盘/读屏测试。
8. **装饰减法**：优先删重复流程、无数据管理按钮、重复示例告示和多余占位；保留一份紧邻动作的安全边界。品牌路线线条可以保留，不应继续增加装饰。

## 修复优先级

- **P1 / 步骤6、11**：示例虚构电话可拨打。只允许本地模拟，清晰反馈“这是示例，不会拨号/预约”。
- **P1 / 步骤5、11**：判断/风险晚于强行动，未知文案暗示持续查询。调整行动卡内信息顺序，并区分加载与无法确认。
- **P1 / 步骤5、11**：确定性文字3.836:1。去掉父透明度或调整语义色，复测所有结果分支。
- **P2 / 步骤1、3**：移动/平板首屏输入迟到。紧凑介绍与输入方式选择，不压缩可读文字。
- **P2 / 步骤7、8**：重做空态，添加第一家店为主操作，无数据隐藏导出/清空。
- **P2 / 步骤6、8、10**：统一个人任务导航与保存入口，历史箭头改成明确“打开记录”，降低相邻删除权重。
- **P3 / 步骤2、3、9、12**：重复流程、链接样式、长邀请码placeholder和说明文案收敛。
